# 다차량 주문 배송 관제 테스트 명세

> **이력·검토 자료.** 아래 내용은 작성 당시의 계획·판정·시험 결과입니다. 수량·구현 상태·배포 여부를 현재 상태로 해석하지 않습니다. 현행 계약과 절차는 [문서 안내](README.md), 후속 전환 조건은 [운영 전환 기준](production-readiness.md)을 사용합니다.

> 2026-09-15 차량 중심 개편: 현재 메뉴는 배차 관리 → 배송 관제 → 자원 관리이며 배차와 관제 모두 지도를 사용합니다. 배송 완료는 사진 선택과 고객 요청 필수 확인 뒤 확인 버튼으로 진행하지만 사진은 서버에 저장하지 않습니다. 날짜별 근무 이력은 현재 완료 목록과 분리한 데모 자료이며 지원배차 등급 계약은 미정입니다. 이번 범위의 완료점은 로컬 구현과 검증입니다.

## 검증 목표

이 명세는 다차량 표본이 원본 시나리오를 훼손하지 않고 차량 중심 배차 관리, 지도 기반 배송 관제, 자원 관리, 배송원 완료 확인과 고객용 ETA 시간대를 일관되게 제공하는지 검증한다. 현재 수량 fixture와 후속 실데이터 기반 동작을 구분하며 로컬 검증과 별도 배포 검증을 섞지 않는다.

## 자동 테스트

### 데이터 규모와 식별자

다음 130대, 4,523곳과 9,090박스는 현재 fixture 회귀값이며 제품의 고정 수량이나 실데이터 importer 계약이 아니다.

- `raw.fleet.vehicles`는 130건이고 V1만 `live: true`다.
- `raw.fleet.deliveries`는 4,515건이며 ID가 `V2-S1`부터 `V130-S35` 규칙을 따른다.
- `adapted.deliveries`는 기존 실시간 8건, `adapted.fleetDeliveries`는 실시간 8건과 합성 4,515건을 합친 4,523건이다.
- 합성 차량 한 대는 2박스 배송지 35곳, 계획 70박스를 가진다. 전체는 4,523곳, 9,090박스다. 합성 차량의 `capacityBoxes`는 `null`이며 70박스를 적재 상한으로 확정하지 않는다.
- 합성 배송지는 `위치 데이터 대기`, `pending`, `결제 완료`를 사용하고 가짜 ETA, 도착, 완료, 알림 시각을 만들지 않는다.
- 모든 배송지는 `vehicle`, `tip`, `notices`, `preciseTimeText`, `customerWindowText`, 시작과 종료 필드를 안정적으로 제공한다.
- 같은 `boot`에서 초기화한 뒤 생성하는 알림 ID는 초기화 전 마지막 ID보다 크다. 서버 재시작으로 `boot`가 바뀌면 고객 팝업 중복 제거 키는 `boot`와 알림 ID를 함께 사용한다.

### 배차 관리 지도와 주문 시나리오

- `mountOrderPlanning({ element, onSelect }).update(data, selectedId)`가 선택 차량과 선택 배송을 반영한다.
- 주문 지도는 고객 뷰어와 같은 로컬 MapLibre·OFM 스타일을 사용하고 `/scenario/api/route-data`에 등록된 좌표만 DSV 목적지 마커로 표시한다.
- 차량은 좌측 목록에서 선택하며 배차 지도에 차량 마커를 만들지 않는다.
- 선택 차량과 무관하게 등록 좌표가 있는 전체 주문 마커를 유지하고 선택 차량의 주문만 앞쪽에 강조한다. 좌표 없는 주문은 전체 위치 미등록 건수로 표시한다.
- 확인되지 않은 좌표와 직선 경로를 만들지 않는다.
- 배차 관리 본문에는 상시 배송량 편집기가 없고 지도 모서리의 `주문 시나리오` 버튼으로 팝업을 연다.
- 팝업은 수신한 전체 배송 박스 합계를 기준 100%로 잡고 목표 물량을 80%부터 120%까지 선택한다. 기본값과 `100% 복귀`는 100%다.
- WebSocket 상태가 바뀌면 새 수신 데이터의 박스 합계, 차량 수와 배송지 수를 사용하되 사용자가 선택한 유효한 목표 비율은 유지된다.
- 80%, 100%, 120% 미리보기 계산이 기준 합계에 일관되게 적용된다. 차량 수와 배송지 수는 데이터 길이를 사용하고 60박스당 필요 차량 추정을 하지 않는다.
- 목표 비율을 바꿔도 원본 스냅샷과 개별 주문 박스 수, 차량·배송지 수, ETA, 알림, 팁과 배송 순서가 바뀌지 않는다.
- 기준 박스 합계가 누락된 데이터는 `미확인`으로 표시하고, 명시적인 빈 배열이나 합계 0은 0으로 표시한다.
- 고정 출발 기준과 전체 배정 배송 완료 예상을 별도 항목으로 표시한다. 완료 예상 데이터가 없을 때 마지막 배송 ETA나 임의 소요 시간을 대신 사용하지 않는다.
- 지도 미리보기 값은 자동으로 증가하거나 연속 애니메이션을 시작하지 않는다.
- 합성 주문을 선택해도 V1 배송 순서 편집, 현재 목적지 또는 완료 명령으로 연결하지 않는다.

### 수동 시나리오 전환

- `set_scenario`는 여섯 프리셋과 `S1`부터 `S8`까지만 허용하고 합성 배송지와 잘못된 값을 거절한다.
- 주문의 `received`, `picking`, `ready`와 배송의 `shipping`, `arrived`, `completed`는 앞 단계나 대기 이벤트 없이 임의 순서로 선택한다.
- 현재와 다른 버튼 한 번은 상태를 한 번만 계산하고 한 번 전파하며 자동 진행 루프를 시작하지 않는다. 같은 프리셋과 배송지를 다시 선택하면 계산과 전파가 없다.
- 합성 배송지를 선택하면 버튼을 비활성화하고 변경할 수 없는 이유를 표시한다.
- 프리셋 변경 전 작성한 배송팁과 운영자 `manual` 고객 안내는 변경 뒤에도 남는다.
- 배송 순서 변경 뒤 프리셋을 적용하거나 `shipping`에서 `arrived`, `completed`로 전환해도 기존 고객 약속 시간대와 정확 ETA 기준은 유지된다. 도착과 완료는 선택 배송의 고정 실제 도착 시각을 제공하며 약속이 없는 경우에만 최초 시간대를 만든다.
- 원시 스냅샷과 어댑터의 `scenarioPreset`, `scenarioStopId`가 현재 선택을 반영한다. 초기화 값은 `received`, `S1`이고 순서 변경, CAS 저장이나 보류 뒤에는 두 값이 `null`일 수 있다.
- 서버는 500ms 시뮬레이션 진행 타이머를 사용하지 않는다. 현재 `OperatingSimulation` 도착은 반복 `tick` 없이 한 번 전환하고, 일반 시뮬레이션 폴백의 최대 10,000회 안전 제한은 유지한다. 인증, 명령 제한 정리와 브라우저 재연결 타이머는 유지한다.
- 이전 `advance`, `place_order`, `speed`, `traffic`, `dwell` 명령은 차단한다. 배송원 화면의 기존 `arrive_stop`은 `arrived` 프리셋으로 한 번만 전환하고 `complete_stop`은 사진 선택과 고객 요청 확인을 거친 확인 동작에서만 `completed`로 한 번 전환한다.
- `/scenario/` 화면 요청은 합본으로 이동하고 route data와 공용 정적 자산은 정상 응답한다.

### 자원 관리와 배송지 선택

- 배송원, 차량, 배송지 탭을 제공하며 탭과 목록의 클릭 영역은 44px 이상이다.
- 배송원 고유 ID가 없으므로 같은 이름을 합치지 않고 차량 ID별 배정 배송원으로 유지한다. 성향, 평가, 업무 지표와 메인 권역은 `미등록`이다.
- 차량의 `region`은 배정 권역으로만 표시하고 실제 차량/배송지 ID로 배정 배송지 조회에 진입한다.
- 확인된 빈 배정은 0으로 표시하되 배송지 또는 박스 데이터가 누락되면 0으로 바꾸지 않고 `미등록`으로 표시한다.
- 배송지 탭은 수신한 차량의 전체 배송지를 조회하며 현재 fixture에서는 130대와 4,523건이 유지된다.
- 검색은 배송지 ID, 배송지명, 주소, 차량 번호와 배송원 이름에 적용한다.
- 차량과 상태 필터를 함께 적용해도 명시적 선택 배송은 사라지거나 V1으로 바뀌지 않는다.
- 전체 4,523건을 검색하되 화면에는 50개 행씩 페이지로 표시한다. 각 행은 데스크톱에서 44px 단일 행이며 한 배송지가 여러 줄 카드로 확장되지 않는다.
- 목록 행 선택은 같은 ID의 선택 카드와 관제 선택을 갱신한다.
- 선택 카드는 배송팁을 표시하고, 합성 배송지의 `미확인` ETA를 값처럼 꾸미지 않는다.

### 고객 알림 명령

- 인증된 동일 Origin 연결에서 알려진 실시간 또는 합성 `stopId`와 1자부터 300자까지의 본문을 허용한다.
- 빈 본문, 공백만 있는 본문, 301자, 문자열이 아닌 본문, 허용되지 않은 제어 문자, `<`, `>`와 알 수 없는 배송지는 거절하고 상태를 바꾸지 않는다. 유효한 본문의 앞뒤 공백은 제거해 저장한다.
- CRLF는 LF로 정규화하고 탭과 LF는 허용한다.
- 성공하면 제목 `운영자 안내`, 종류 `manual`, 채널 `고객 팝업`, 상태 `시연 발송`, 시각, 대상, 본문과 작성자를 가진 알림을 한 건만 만든다.
- 결과는 모든 인증 연결에 전파되지만 외부 발송 성공으로 표시하지 않는다.

### 고객 알림 보존 범위와 조회 비용

- 한 정차지에 51건을 추가하면 가장 오래된 1건이 제거되고 최근 50건만 시간 순서대로 남는다.
- 여러 정차지에 걸쳐 1,001건을 추가하면 전역에서 가장 오래된 1건이 제거되고 최근 1,000건만 남는다.
- 정차지별 50건 제한을 적용한 뒤 전체 1,000건 제한을 적용한다.
- 보존 범위에서 제거된 오래된 알림은 관제와 고객 화면에 나타나지 않으며, 화면은 전체 영구 이력으로 표시하지 않는다.
- 정리 뒤에도 새 알림 ID는 이전 마지막 ID보다 크다. 초기화로 이력을 비운 뒤에도 ID를 재사용하지 않는다.
- 어댑터가 4,523개 배송을 변환할 때 알림 배열을 배송마다 다시 전체 검색하지 않고 한 번 만든 `stopId` 인덱스를 재사용한다.
- 인덱스 변환 뒤 각 배송에는 자기 `stopId`의 알림만 원래 순서대로 들어간다.

### 사용자 단위 명령 속도 제한

- 같은 사용자 이름으로 연 두 WebSocket의 명령을 합산해 이동식 1초 구간의 처음 10건을 허용한다.
- 같은 구간의 11번째 명령을 보낸 WebSocket만 코드 `4429`로 닫고 다른 연결은 계속 상태를 받는다.
- 다른 사용자 이름의 연결은 앞 사용자의 10건에 영향을 받지 않는다.
- 시뮬레이션 `reset` 뒤에도 아직 1초가 지나지 않은 사용자 속도 기록은 유지되고, 1초가 지나면 만료된다.

### 배송팁 명령

- 알려진 실시간 또는 합성 `stopId`와 1자부터 500자까지의 본문을 허용한다.
- 500자는 저장하고 빈 값, 공백만 있는 값, 501자, 문자열이 아닌 값, 허용되지 않은 제어 문자, `<`, `>`와 알 수 없는 배송지는 거절한다. 유효한 팁의 앞뒤 공백은 제거해 저장한다.
- CRLF는 LF로 정규화하고 탭과 LF는 허용한다.
- 저장 결과는 `body`, 선택 차량의 시연 배송원 `author`, `updatedAt`으로 운영, 자원 관리 배송지 탭과 배송원 뷰어에 같은 값으로 나타난다.
- 저장 요청 직후가 아니라 새 스냅샷에서 같은 값이 확인된 뒤에만 완료 상태를 표시한다.

### 고객 ETA 시간대와 지연 임계값

각 테스트는 고객별 최초 정확 ETA를 기준 0분으로 설정한다.

| 변화 | 기대 결과 |
|---|---|
| +29분 | 운영 정확 ETA만 갱신, 고객 시간대와 지연 알림 유지 |
| +30분 | 운영 정확 ETA만 갱신, 지연 알림 없음 |
| +31분 | 지연 알림 1건, 고객 시간대 갱신, +31분을 새 기준으로 설정 |
| +15분 후 추가 +16분 | 누적 +31분에서 지연 알림 1건 |
| +31분 상태 재계산 | 새 기준 대비 0분이므로 반복 알림 없음 |
| 새 기준에서 다시 +31분 | 새 지연 알림 1건과 새 시간대 |
| -31분 조기 변경 | 운영 정확 ETA만 갱신, 고객 기준과 시간대 유지, 지연 알림 없음 |

- 고객 시간대의 시작은 약속 기준 30분 전, 종료는 30분 후다.
- 초기화와 최초 ETA 산출은 고객별 기준을 새로 설정한다.
- `±15분 이내 80% 이상` 정확도 목표를 고객 시간대 폭이나 알림 임계값으로 사용하지 않는다.

### 고객 신규 알림 팝업

- 최초 연결 시 기존 알림 이력을 렌더링하지만 팝업으로 재생하지 않는다.
- 현재 고객과 같은 `stopId`에 새 ID가 추가될 때만 팝업을 한 번 연다.
- 자동 ETA 알림의 정확 시각은 고객 시간대로 표시하지만, `manual` 알림 본문은 ETA 형식의 시각이 포함되어도 원문을 유지한다.
- 다른 고객 알림, 같은 ID 재수신과 정렬 변화는 팝업을 열지 않는다.
- 사용자가 팝업을 닫은 뒤 같은 상태를 다시 받아도 다시 열지 않는다.
- `boot`가 바뀐 첫 스냅샷은 새 기준 이력으로 등록하고 과거 알림을 팝업으로 열지 않는다.

### 배송원 입력 보존과 교차 뷰

- 배송원이 배송팁을 입력하는 동안 시뮬레이션 시각이나 ETA 스냅샷이 와도 입력값과 커서가 유지된다.
- 저장이 확인되면 배송원, 자원 관리 배송지 선택 카드와 배송 관제에서 같은 팁을 표시한다.
- V2 배송지를 선택해 배송원 뷰어로 이동하면 선택 차량 V2와 예시 배송원 002를 표시하고, 저장된 팁의 작성자도 예시 배송원 002다.
- 합성 차량 문맥에서는 V1 현재 목적지와 배송 완료 버튼을 노출하거나 활성화하지 않는다.
- 다른 배송지를 선택하면 저장되지 않은 입력을 조용히 다른 배송지에 적용하지 않는다.
- 배송원 메뉴는 금일 배차와 근무 이력이며 날짜별 근무 이력은 별도 데모 자료를 사용한다. 현재 완료 배송지를 과거 이력으로 재사용하지 않는다.
- 연결된 V1의 현재 배송지가 실제 도착 상태일 때 사진을 선택하고 고객 요청 이행을 필수 확인해야 완료 확인 버튼을 사용할 수 있다.
- 사진은 브라우저 임시 미리보기이며 서버 저장, 재조회와 외부 전송 결과를 표시하지 않는다. 확인 버튼은 기존 완료 명령을 한 번만 보낸다.

### 차량 중심 관제와 회귀

- 차량 목록은 기본 주문 수신 순서를 유지하며 남은 배송지 수와 박스 수를 비교한다. 가구 수로 환산하지 않는다.
- 제공되지 않은 예상 소요 시간은 `미등록`으로 두고 임의 산식을 만들지 않는다.
- 차량을 선택하면 관제 지도에 출처가 확인된 현재 위치와 남은 등록 배송지 마커를 표시한다. 상세 배송지를 바꿔도 차량 운행 요약은 유지된다.
- 우측 차량 카드에서 배송지별 상세를 펼치고 실제 사건을 시간순으로 표시하며 같은 배송지 ID의 고객 알림만 함께 조회한다.
- 지원배차는 진입점과 원자료 미연결 상태를 표시한다. 안정 등급, 호출, 수락과 재배정 결과를 임의로 만들지 않는다.
- 장치 상태 영역은 없고 실시간 V1 배송 관리만 기존 보호 조건 아래 제공한다.
- `set_route_order`는 V1의 8개 배송지만 받고 합성 ID를 거절한다.
- 현재, 완료, 보류 배송 잠금과 stale route CAS 검증이 유지된다.
- `set_scenario`, 인증, WebSocket Origin, 세션 만료와 원본 스냅샷 SHA 회귀 테스트가 통과한다.
- 장시간 알림 생성에서도 정차지별 50건과 전체 1,000건을 넘지 않고 4,523개 배송 변환 결과가 정차지별로 격리된다.
- 사고와 정차 지연 버튼은 합본 가이드와 운영 화면 DOM에 없지만 원본 시뮬레이션 알고리즘 테스트는 계속 통과한다.

## 브라우저 검증

### 1280px

- 운영 메뉴가 배차 관리 → 배송 관제 → 자원 관리 순서로 표시되고 이전 해시 경로는 대응 화면을 연다.
- 배차 지도가 본문을 채우고 고객 뷰어와 같은 OFM 테마, 전체 등록 주문 마커, 선택 차량 강조, 위치 미등록 건수와 주문 시나리오 팝업을 보여 준다. 차량 마커는 없다.
- 전역 가이드의 주문 세 버튼과 배송 세 버튼을 임의 순서로 선택하고 합성 배송지에서는 읽기 전용 상태를 확인한다.
- 자원 관리의 배송원/차량/배송지 탭에서 검색, 선택, 실제 ID 기반 배정 배송지 조회와 배송팁이 작동한다.
- 배송 관제에서 차량별 잔여량, 지도, 우측 차량 카드와 배송지 상세가 연결되고 상세 열람 중 차량 요약이 바뀌지 않는다.
- 배송원 뷰어에서 금일 배차와 날짜별 데모 근무 이력을 분리하고 사진/고객 요청 확인 전후 완료 버튼 상태를 확인한다.
- 고객 알림 입력 팝업에서 대상, 300자 제한, 취소와 확인을 키보드로 조작한다.

### 390px와 320px

- 세 운영 페이지, 고객 뷰어와 배송원 뷰어에 가로 넘침이 없다.
- 주문 지도와 주문 시나리오 팝업이 화면 안에 머물고 목표 물량과 100% 복귀를 조작할 수 있다.
- 여섯 시나리오 버튼은 44px 이상의 조작 높이를 유지하고 사고, 정차 지연, 자동 진행과 배속 컨트롤은 나타나지 않는다.
- 자원 탭과 목록은 내부에서 스크롤되고 검색, 선택과 44px 이상의 터치 목표를 유지한다.
- 관제 차량 목록, 지도와 우측 상세가 한 열로 쌓여도 잔여량과 선택 관계를 잃지 않는다.
- 배송 완료 사진 미리보기와 고객 요청 확인 팝업이 폰 화면 안에 머물며 서버 사진 저장을 암시하지 않는다.
- 고객 신규 알림 팝업과 운영자 안내 팝업은 화면 안에서 제목, 본문과 닫기 동작을 모두 보여 준다.
- 배송팁 입력 중 실시간 갱신이 와도 키보드 입력을 잃지 않는다.

브라우저 콘솔 오류와 처리되지 않은 Promise rejection이 없어야 한다. 세 해상도에서 문서 너비가 뷰포트 너비를 넘지 않는지 수치로 확인한다.

## 관제 기록 재배치 회귀 (2026-09-15)
- 배송지 펼침에는 주소/물량/ETA/요청/팁과 이력·알림 보기만 있고 기록 목록은 없다. 진입 후 관리 대상이 그 배송지이며 가운데 현재 차량 요약은 바뀌지 않는다.
- 전체/처리 이력/고객 알림 필터는 동일 대상의 실제 시간순 기록만 보여준다. 고객 알림 본문은 펼쳐 읽으며 다른 배송지 알림이 섞이지 않는다.
- 관리 배송지 변경, 차량 변경, 선택 배송지 삭제/재수신에 URL/기록/지도/편집 대상이 같은 차량 안에서 일치한다.
- 배송 순서 관리 진입은 바로 편집 초안을 연다. 취소는 미저장 변경을 버리고 이력 화면으로 돌아간다. 초기화는 마지막 저장 순서로 초안만 복구하고, 저장 확인 후에도 편집 화면에 남는다. 별도 돌아가기 버튼은 없다. 저장/취소, 현재/완료 배송지 이동 금지, 합성 차량 명령 차단, 오래된 상태 거부가 유지된다.
- 320/390px에서도 문서/기록 목록 가로 넘침이 없고 버튼/필터와 대상 선택은 기록 스크롤 영역 밖에 있다.
