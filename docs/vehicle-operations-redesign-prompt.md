## 반드시 반영할 요구사항

1. **운영 메뉴:** 주문 관리를 배차 관리로, 배송 목록을 자원 관리로 바꿔라. 표시 순서는 배차 관리 → 배송 관제 → 자원 관리다.
2. **배차 지도:** 차량 마커를 제거하고 차량을 좌측 리스트에 나열하라. 전체 주문 마커를 계속 표시하면서 선택 차량의 주문 마커를 앞쪽에 강조하라. 다른 차량의 주문을 숨기거나 좌표를 움직이지 마라. 좌표 없는 주문은 미등록 건수로 설명하라.
3. **배차 지표:** 차량별 고정 출발 시각과 전체 배정 주문의 완료 예상 시각을 구분해 보여라. 주문 시나리오 팝업에 총 차량, 배송지/가구, 박스, 소요 시간, 기사별 박스/가구 정보를 넣어라. 실데이터 합계 기준 80–120% 미리보기는 유지하고 원본 주문/배정/ETA를 임의 변경하지 마라.
4. **권역 제한:** 차량별 폴리곤, 내부 배송지/박스 수, 주변 가구와 핀배차 편집은 미래 개념이다. **실제 권역이 나오기 전에는 예시 문구만 둬라. 가짜 폴리곤, 내부 집계, 편집, 핀배차 동작과 임의 알고리즘은 구현하지 마라.**
5. **배송 관제:** 차량별 남은 가구 수, 박스 수와 예상 소요 시간을 메인으로 삼아 정렬/비교할 수 있게 하라. 차량을 선택하면 현재 위치와 남은 배송지 마커, 지원배차 진입점을 보여라. 지원배차는 주변 차량의 안정 레벨 상/중/하를 보고 호출/지시하는 요구다. 산식이나 명령 계약이 없으면 임의 점수와 성공 결과를 만들지 마라.
6. **관제 상세:** 차량 선택 → 우측 카드 상세 → 배송지별 펼침으로 이해하고 구조를 잡아라. 배송 타임라인과 사건 이력을 실제 사건 기준으로 통합해 시간순으로 보여주고 해당 배송지의 고객 알림을 함께 조회하게 하라. 상세 열람으로 현재 차량의 운행 요약이 바뀌지 않게 하라. 냉장고 안/문 앞 같은 고객 요청을 시각적으로 표시하라.
7. **자원 관리:** 배송원 / 차량 / 배송지 탭을 만들고 배송원의 성향, 지표, 메인 권역과 배송지 팁을 연결하라. 데이터가 없는 평가와 지표는 꾸며내지 마라.
8. **배송원:** 완료 이후 촬영하는 카메라 UI와 고객 요청 이행 확인 팝업을 제공하라. 단, 촬영을 여는 완료가 어떤 상태인지와 사진 후 최종 확정/필수 여부는 아직 미정이므로 그 상태 전이를 임의 확정하지 마라. 현재 배송지 우측 상단의 요청 아이콘은 선택 사항이다. 진행 배차 / 종료 배차를 금일 배차 / 근무 이력으로 바꾸고 날짜별 캘린더 조회를 제공하라. 현재 완료 목록을 과거 이력으로 가장하지 마라.

## 구현 전에 문서로 남길 것

`docs/vehicle-operations-redesign-plan.md`를 기준으로 화면 구조, 요구 ID별 변경 범위, 현재 코드 근거, 필요한 데이터, 데이터가 없는 상태, 작업 순서와 검증 기준을 정리하고 저장하라. 확정 요구와 미정 업무 규칙을 구분하라. 이후 `DESIGN.md`와 관련 기존 운영 문서의 충돌 부분을 이번 결정에 맞춰 갱신하라.

다음은 추가 결정이 필요한 항목이다: 사진과 최종 완료의 관계, 지원배차 안정 레벨/수락/재배정 기준, 전체 소요 시간의 집계, 가구와 주문의 집계 단위, 기본 정렬 기준, 배송원 지표/고객 요청 분류/근무 이력의 데이터 계약. 필요한 질문은 초기에 간결하게 묶어 전달하고 독립적으로 진행할 수 있는 작업을 계속하라. 답이 없다는 이유로 업무 규칙을 임의 확정하지 마라. 일반적인 UI 배치와 되돌릴 수 있는 구현 선택은 기존 패턴에 맞춰 직접 결정하라.

## 유지할 조건

- 차량당 약 70박스와 35곳은 규모 가정이며 고정 배차량이나 용량 제한이 아니다.
- 기존 DSV 계열 OFM 지도 스타일, 접힌 출처 표기, Command/Control + 휠 확대와 안내 가리개를 유지하라. 도로 경로 대신 직선을 그리지 마라. 예시 차량 위치를 지원배차의 실제 위치로 사용하지 마라.
- 공통 폰 프레임과 크기, 폰 내부 시계, 기존 고객 매장 선택/알림 벨/모두 읽기/삭제/새 알림 팝업을 유지하라. 배송원 지도 마커 50% 축소, 고객 매장 집 모양과 라임 차량 디자인도 보존하라.
- 장식용 가운데점과 기본 이모지 아이콘을 남발하지 마라. SVG 아이콘과 클릭 영역의 중심을 맞춰라. 지역명 내부의 `송파·강남` 같은 표기는 유지해도 된다.
- 운영 이력에는 실제 발생한 업무 사실만 표시하고 수동 시나리오 조작 문구를 넣지 마라. 시나리오와 고객 알림의 연동은 유지하라.
- 인증, 경로 편집의 저장/취소와 오래된 상태 저장 거부, 현재/완료 배송지 보호를 보존하라. 합성 차량 선택이 V1의 운행 명령으로 이어지지 않게 하라.
- 외부 데이터, 영구 이력, 사진 저장, 외부 기사 지시가 연결되지 않았다면 완료됐다고 표시하지 마라. 이번 기본 범위는 로컬 구현과 검증이며 배포는 별도 요청 때 수행하라.

## 작업과 완료 보고

확정된 작업은 코드 수정, 관련 테스트, 브라우저 확인과 문서 갱신까지 자율적으로 완료하라. 독립적인 작업에만 파일 소유 범위를 지정해 native subagent를 활용하고 공유 파일 변경을 조정하라. 기존 의존성과 패턴을 우선 사용하라.

변경 동작에 맞는 집중 테스트를 먼저 실행하고 `npm test`, 수정 JavaScript 문법 검사, `git diff --check`를 수행하라. 전송이나 대량 렌더링을 변경하면 기존 용량 검사도 필요한 범위에서 실행하라. 모든 운영 메뉴와 배송원 탭, 고객 회귀 화면을 실제 브라우저에서 확인하라. 전체 주문 유지/강조, 잔여량 갱신, 이력/알림의 대상 일치, 권역 기능 미구현, 좁은 화면과 아이콘 정렬을 검증하라.

계획 문서에 요구 ID별 결과와 검증 근거를 남겨라. 마지막에는 구현 내용, 확인한 동작, 실제 데이터 또는 업무 결정 때문에 남은 항목을 구분해 보고하라. 대기 기능이 있으면 전체 완료로 보고하지 말고 독립적으로 끝낼 수 있는 나머지 작업은 마쳐라.
