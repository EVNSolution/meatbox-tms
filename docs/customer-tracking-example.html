고객 실시간 조회 예시

미트박스가 만들 화면의 그림이다. 우리 서버가 보내는 메시지만으로 이 정보를 채울 수 있는지 보여 준다. 모든 값은 합성 데이터다.

파란 라벨은 값이 오는 곳이다: 연동 계약 3장의 메시지(3.1 배송 상태, 3.2 ETA, 3.3 온도)와 필드 이름이다.

A. 배송 중인 주문

주문 MB-20261102-48213

품목 3개 · 합성 가게 배송
3.1 · orderId, items[]

배송 상태

  1. 배차 완료
    09:05
    3.1 · status=dispatched · occurredAt
  2. 기사 출발
    09:12
    3.1 · status=departed · occurredAt
  3. 곧 도착
    다음 배송지가 되면 표시
    3.1 · status=arriving

    계약에는 있지만 현재 서버는 보내지 않는다(다음 배송지가 되는 시점을 아직 정하지 않았다).

  4. 배송 완료
    완료되면 시각 표시
    3.1 · status=delivered · occurredAt

도착 예정

오전 9:58
오전 9:40 앞 배송 순서가 바뀌어 갱신
3.2 · stops[].eta (orderIds에 이 주문이 든 항목)
3.2 · reason=reordered, computedAt

ETA는 차량 전체 목록으로 온다. 이 주문의 항목을 orderIds로 찾는다. 갱신 이유는 reason 값으로 문구를 고른다.

reason고객에게 보일 문구 예
departed기사가 출발했습니다
reordered배송 순서가 바뀌어 갱신했습니다
delayed앞 배송이 지연되어 갱신했습니다
zone_entered배송 지역에 들어와 갱신했습니다
completed앞 배송이 끝나 갱신했습니다

배송 사진

완료되면 사진이 여기에 표시된다
3.1 · photos[] (status=delivered)
3.1 · note

사진 링크는 지금 우리 세션이 있어야 열린다. 미트박스가 받아 보여 주려면 서명 링크가 필요하다(후속 작업).

차량 온도

3.3 · measurements[].celsius 3.3 · measurements[].measuredAt 3.3 · vehicleId, sensorId

온도는 차량 단위로 온다. 이 주문의 차량은 3.1의 vehicleId로 찾는다. 측정이 없는 구간은 비워 둔다.

B. 배송하지 못한 주문

주문 MB-20261102-48220

3.1 · orderId

배송 상태

  1. 배차 완료
    09:05
    3.1 · status=dispatched
  2. 기사 출발
    09:12
    3.1 · status=departed
  3. 배송하지 못했습니다
    10:03
    3.1 · status=failed · occurredAt

사유

받을 사람이 없어 전달하지 못했습니다.
3.1 · failure.reasonCode=ABSENT
3.1 · failure.note
reasonCode고객에게 보일 문구 예
ABSENT받을 사람이 없었습니다
ACCESS_DENIED출입이 되지 않았습니다
ADDRESS_MISMATCH주소를 찾지 못했습니다
REFUSED수령이 거절되었습니다
NO_STORAGE보관할 곳이 없었습니다
OTHER기타 사유 (note 참고)

부분 완료(partially_delivered)는 items[]의 orderedQty와 deliveredQty로 보여 준다.

이 파일은 외부 요청 없이 열리는 한 장짜리 예시다. 미트박스 화면의 디자인을 정하지 않으며, 제안하는 것은 값의 출처뿐이다. 메시지 본문은 연동 계약을 따른다.
