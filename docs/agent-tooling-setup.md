# 미트박스 Agent 도구 설정

2026-10-05, Asia/Seoul. 이 대화에서 승인된 기술 방향과 프로젝트 작업 기준입니다. 전역 OMX/Ponytail 설정을 대체하지 않습니다.

## 승인된 기술 방향

- 새 서버: Kotlin/JVM + Spring Boot.
- 웹: 기존 HTML·CSS·ES 모듈 UI를 `apps/web/` 단일 프런트 패키지로 완전히 포크합니다. 기존 JS/MJS를 보존하며 새 코드와 변경 경계는 TypeScript로 구현하고, Vite 하나로 개발·빌드합니다.
- 새 개발 경로는 `services/api/`와 `apps/web/`입니다. 기존 UI 포크와 Node 연결을 거쳐 TEST의 인증·원본 조회·배차·자원을 Kotlin으로 이관했습니다. 검증한 실행·자료 보존 범위는 [이관 기록](kotlin-state-migration-result.md)과 [데모 삭제 결과](demo-removal-result.md)를 따릅니다.
- 한 Git 저장소에서 두 모듈을 독립적으로 빌드합니다. 새 프런트를 기존 API에 먼저 연결하고, Kotlin API는 상태 쓰기 소유권을 지키며 이어서 이관합니다.
- 운영·QA·테스트 서버에는 같은 제품을 배포하고 데이터·계정·비밀값·외부 연결을 환경별로 격리합니다. 필요한 메모리는 증설할 수 있으며, 환경별 소스 분기나 별도 프런트 패키지를 만들지 않습니다.
- 당분간 테스트 서버 한 대만 사용합니다. 로컬 합성 자료와 TEST에서 이관·복구를 검증했고, QA·운영 서버 생성은 후속 범위로 둡니다.
- 기존 데모와 중복 웹은 실제 삭제했습니다. Node 공용 계산·저장 모델과 이전 릴리스는 계약 비교·복구 근거로 유지합니다. 코드가 있다는 이유만으로 제품 계약이나 운영 완료로 간주하지 않습니다.
- 언어 변경, 데모 제거, 데이터 이행을 각각 검토합니다. 기존 확정·진행 상태를 보존하며, 같은 업무 상태를 기존 서버와 새 서버가 동시에 쓰도록 구성하지 않습니다.

이 결정은 [프런트 포크·새 백엔드 계획](new-stack-architecture.md)에 고정했습니다. 탐색은 화면·서버 주입·동작 계약을 대조하는 단계이며 언어·모듈 방향을 다시 선택하지 않습니다.

Attention-kind는 [설치한 스킬](../.codex/skills/attention-kind/SKILL.md), Karpathy 원칙은 [프로젝트 작업 스킬](../.codex/skills/meatbox-work-unit/SKILL.md)과 [검토한 원문](https://github.com/multica-ai/andrej-karpathy-skills/blob/2c606141936f1eeef17fa3043a72095b4765b9c2/CLAUDE.md)을 기준으로 합니다.

Anti Slop은 Kotlin 원본을 검사하지 않습니다. TypeScript 중심 규칙을 기존 JavaScript에 일괄 강제하지 않으며, 런타임 입력 검증이나 필요한 테스트를 제거해서 lint를 통과시키지 않습니다. HTML 인라인 스크립트는 Oxlint 검사 경로와 별도로 확인합니다.

## 한 번의 구현 단위

구현 전에 다음 항목을 짧게 정합니다. 저장소에서 확인할 수 있는 사실은 직접 확인하고, 결과를 실질적으로 바꾸는 미확정 요구만 사용자에게 묻습니다.

1. **요구 동작:** 사용자가 어떤 입력·행동을 하면 어떤 결과를 얻어야 하는가.
2. **범위:** 이번에 변경할 화면/API/상태와 데이터 소유자는 무엇인가.
3. **가정과 근거:** 확정된 사실과 미확정 계약은 무엇인가. 안전한 가정은 명시하고 진행한다.
4. **완료 조건:** 정상 경로와 중요한 거부·충돌·저장 실패 경로에서 무엇을 관찰해야 하는가.
5. **검증:** 동작 테스트, API 계약 테스트, 브라우저 확인 중 해당 변경을 입증할 최소 검증은 무엇인가.

각 변경은 이 단위의 요구 동작과 연결합니다. 사전 존재하는 문제를 발견하면 근거와 함께 기록하고, 현재 범위가 허용하는 부분을 처리합니다. 데모 정리가 명시된 범위에서는 기존 데모 코드의 삭제도 계획과 회귀 기준에 따라 수행합니다.

검증은 위험과 변경 크기에 비례합니다. 컴파일·lint 통과를 배차·배송·권한 동작의 성공으로 대체하지 않습니다. 신뢰 경계의 입력 검증, 데이터 손실 방지, 보안, 접근성, 명시된 요구는 단순화를 이유로 생략하지 않습니다.

## 현재 개발 도구 확인

- 셸에서 OpenJDK/Javac 21.0.11 실행 성공.
- JAVA_HOME은 Homebrew JDK 21의 Contents/Home을 가리킵니다. macOS java_home의 시스템 등록 목록은 해당 JDK를 찾지 못했지만, 실제 java/javac 실행은 정상입니다.
- 전역 Gradle과 kotlinc는 없습니다. 새 서버에는 Gradle Wrapper와 Kotlin Gradle 플러그인을 사용하므로 전역 설치를 선행 조건으로 두지 않습니다.
- 새 서버는 Spring Boot 4.1.1이며 인증·배차·자원과 실제 JAR 계약을 검증했습니다. 새 웹은 로그인·등록·운영·디자인 가이드 네 HTML 진입점을 단일 Vite 패키지에서 빌드합니다. 보호 게이트웨이는 native에서 Kotlin에 연결하며 Node 연결은 호환 비교 모드로 남깁니다.
- 설치·검사·실행은 [새 기술 스택 개발 환경](new-stack-development.md)을 따릅니다. 로컬 도구는 Node 26.3.1·npm 11.16.0을 확인했습니다.
- detekt와 Oxlint JavaScript plugin API는 알파 상태입니다. 버전을 고정해 검증했고, 업데이트할 때 Kotlin·Gradle·플러그인 로딩 호환성을 다시 확인합니다.

## 다음 탐색의 완료 기준

제공하기로 한 동작을 문서·기존 코드·테스트와 대조해, 실제 구현된 부분과 데모 또는 미확정 연동을 구분합니다. API·상태 소유권, 권한, 저장·복구, 실제 외부 입력을 우선 확인하며, 탐색에서 찾은 동작 계약을 새 구현의 테스트 기준으로 연결합니다.

기존 [운영 준비도](production-readiness.md)는 현재 구현과 운영 증거의 경계를 확인하는 출발점입니다. 준비된 CSV/JSON으로 실제 미트박스 API·취소·변경·인증 계약을 추정하지 않습니다.
