# 프런트/API 연결과 TEST 배포 결과

2026-10-05, Asia/Seoul. 새 프런트와 Kotlin API를 기존 TEST 공개 경로에 연결했다. 최초 전환, 명시적 코드 롤백, 같은 릴리스 재적용, API·웹 재시작과 인증 브라우저 조회를 검증했다. QA·운영 서버는 생성하거나 변경하지 않았다.

## 현재 실행 구조

공개 주소는 `https://3.36.96.156/combined/`다. Caddy의 기존 fallback 한 줄만 Node `3001`에서 보호 웹 gateway `4173`으로 변경했다. `/push-lab` 설정의 나머지 바이트와 두 Push Lab 서비스의 PID·재시작 수는 유지됐다. 내부 세 서비스는 loopback으로만 수신한다.

| 소유자 | 현재 역할 |
| --- | --- |
| `apps/web` | 운영 화면과 보호 정적 파일; 현재 포크에 남은 과거 데모는 삭제 대상 |
| Kotlin `services/api` | manifest, 날짜별 원본, 권역, 누적 배송지의 GET/HEAD; 자원 등록부 조회와 네 저장 API |
| 기존 Node | 로그인·세션·계정, 날짜별 배차 state/commands·checkpoint, 레퍼런스 WebSocket |

Node와 웹은 같은 `owners.env`를 읽는다. 자원 소유자가 Kotlin이면 Node는 자원 DB를 열지 않고 인증된 자원 경로에 `503 RESOURCE_OWNER_MOVED`를 반환한다. Kotlin 장애에도 웹은 Node 자원 writer로 우회하지 않는다.

복구 명령과 설정은 [배포 도구 설명](../deploy/new-stack/README.md)에 있다. 새 API·웹 서비스는 부팅 자동 시작을 설정했다. 실제 호스트 재부팅은 실행하지 않았으며 서비스 재시작으로 검증했다.

## 코드와 실제 데이터 검증

- 기존 서버 테스트 **498/498**, 프런트 테스트 **272/272**, 빌드 산출물 검사 **3/3**, Kotlin 테스트 **40/40**, 실제 JAR 연결 테스트 **24/24**, provenance 검사 **7/7** 통과.
- 타입 검사·프런트 lint·Kotlin detekt·빌드·Node/셸 구문 검사·패키징 검사 통과. 기존 Anti Slop 경고 두 건은 baseline으로 유지했다.
- 실제 53,913,844바이트 배송지 catalog를 스트리밍 검증했다. 기본일 `2026-09-16`의 170페이지와 마지막일 `2027-07-30`의 296페이지 전체, 검색·페이지 보정·누적 집계·네 원본 읽기 JSON이 Node와 일치했다.
- JDK 정렬에서 발견한 공백·구두점 순서 차이는 실제 Node와 같은 ICU 78.2로 수정했다. 직접 만든 숫자 비교기를 삭제했다.
- 실제 자원 SQLite 복사본에서 네 저장 동작을 Node golden 복사본과 비교했다. stale revision은 409, 같은 revision의 동시 요청은 200/409 한 쌍으로 끝났으며 저장 revision 5가 JVM 재시작 뒤 유지됐다. 실제 원본 DB에는 검증용 저장을 실행하지 않았다.
- 원본 DB와 기존 두 checkpoint의 SHA256은 후보 검증·전환·롤백·재적용 이후 동일했다. 실제 자원 revision은 0, 기존 날짜별 state revision은 9를 유지했다.
- 공개 HTTPS에서 인증서 검증, 비인증 401/보호 파일 302, 인증 자산 200·배포 HTML 바이트 일치, Secure/HttpOnly/SameSite=Strict 쿠키, Kotlin reader/owner 표시, Origin 403와 revision 409 거부를 확인했다.
- 인증 브라우저에서 확정 **155대·주문 2,552건·4,680박스**, 자원 차량 **31대**, 관제 완료 1건과 기사·고객 이력 조회를 확인했다. 고객 매장 검색과 다음 페이지 이동도 동작했고 브라우저 오류·경고는 없었다. 실제 업무 상태를 계산·전송·출발·완료시키는 조작은 수행하지 않았다.

## 서버 용량과 남은 경계

현재 TEST 인스턴스는 기존 `meatbox` 한 대다. EBS snapshot을 확보하고 root 볼륨을 8→24GiB로 확장했으며, Java 21과 2GiB swap을 설치했다. 배포 후 root 여유는 약 14GiB다. 기존 Push Lab 두 서비스는 이 과정에서 재시작하지 않았다.

JVM heap은 128MiB, 서비스 메모리 상한은 320MiB다. 대형 실제 자료 검증에서 cgroup peak는 299,253,760바이트, 최종 서비스 재시작·공개 smoke 후 peak는 276,037,632바이트였고 OOM·비정상 재시작은 0이었다. 동시 대형 읽기 부하와 QA·운영 메모리 상한은 별도 승격 검증이 필요하다.

이 배포는 프런트 연결과 첫 Kotlin 소유 단위의 TEST 전환이다. 계정·날짜별 배차 writer의 완전한 Kotlin 이관, tenant/역할·기사/고객 권한 분리, 실제 공급자 주문 계약·GPS·사진·알림은 완료 범위에 포함되지 않는다. 기존 Node와 복구 릴리스는 이 경계와 복구 경로가 해소되기 전 삭제하지 않는다. 사용자는 과거 기사·고객 및 테스트 시나리오 데모를 제품 유지보수 대상에서 제외하고 삭제 대상으로 지정했다. 위 브라우저 조회는 연결 검증 기록이며 해당 데모를 제품으로 유지하겠다는 결정이 아니다. 현재 삭제 범위는 [프로젝트 구조 안내](project-structure.md)에 기록한다.

서버·브라우저 증거는 Git에 포함하지 않는 `.runtime/new-stack-deploy/`와 서버의 제한된 검증 백업 디렉터리에 보관한다. 임시 검증 계정은 비활성화했고 해당 세션이 401로 거부되며 브라우저가 로그인으로 돌아가는 것을 확인했다. 기존 사용자·초대 값과 계정 파일의 0600 권한·서비스 사용자 소유권을 유지했다. 검증용 평문 비밀번호·쿠키·SSH 키와 임시 브라우저 탭·SSH 연결을 제거했다. 중지한 후보 JVM의 자료 복사본도 제거한 뒤 업무 파일·Push Lab·서비스 상태를 다시 확인했다.
