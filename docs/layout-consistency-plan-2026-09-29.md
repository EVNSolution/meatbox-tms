# 화면 계층·정렬 일치 계획 (2026-09-29)

## 목표와 기준

2026-09-29 전체 화면 점검에서 확인한 정렬, 가림, 오래된 정보 표시를 현행 [DESIGN.md](../DESIGN.md)에 맞춘다. 운영·고객·배송원·인증 화면과 루트 `previews/terminal-view/#/design`의 표본을 검토한다. 보존 원본 `workspaces/`와 주문·배차 데이터 계약은 변경하지 않는다.

적용 규칙은 다음과 같다.

1. 같은 조작 행의 입력·선택기·버튼은 44px 높이와 상단 기준선을 공유한다. 상태·집계는 조작과 별도 영역에서 읽히게 한다. 상태 배지와 본문 정보까지 기계적으로 44px로 늘리지 않는다.
2. 로딩·빈 날짜·과거 조회에는 선택 날짜와 읽기 전용 여부를 가까이 표시하고 이전 날짜의 요약을 남기지 않는다.
3. 320px 이상에서 고정 조작, 저장 바, 팝오버가 행·빈 상태·트리거를 가리지 않는다. 제목의 프로그램적 포커스는 유지하고 시각 표현을 정리한다.
4. 고객·배송원 뷰어에는 운영 rail을 예약하지 않는다. 내부 모바일 프레임의 배치는 프레임 너비를 기준으로 한다.
5. 인증 화면과 로컬 디자인 가이드는 현행 공식 자산과 메뉴 계층을 보여 준다. 역사적 결정은 이력으로 남긴다.

## 수정 순서

| 단계 | 대상 | 완료 조건 |
|---|---|---|
| 1 | 배차·관제·자원 관리 | 배차 과거 날짜 상태를 날짜 툴바에 표시, 320px 날짜 조작 44px 유지, 자원 표와 저장 바 분리, 상단 조작 높이 일치, 시나리오 버튼·지역 패널·제목 포커스의 가림 제거 |
| 2 | 고객·배송원 | 고객 선택 화면 좌측 72/92px 빈 여백 제거, 현재 날짜 문맥 표시, 배송원 빈 날짜의 이전 요약 제거, 좁은 폰 안의 제목·액션과 조회 전용 상태 정렬 |
| 3 | 인증·로컬 가이드 | 로그인·가입·오류 화면을 현행 브랜드·헤더·폼 위계에 맞춤, 가이드 메뉴 구조와 날짜 툴바 밀도를 실제 제품에 맞춤 |
| 4 | 검증·배포 | 관련 회귀와 전체 테스트, 1440/390/320px 실제 렌더링, 후보 SHA와 운영 자료·상태 호환성 확인 후 런북대로 배포·사후 확인 |

## 배포 판단

배포 후보는 한 커밋과 테스트 결과로 고정한다. [운영 절차](operations.md)의 사전 읽기 점검, 상태·계정·자원 DB의 호환성과 일관된 백업·복원 계획, 현재 활성 릴리스 대조가 통과해야 운영 서버를 변경한다. 인증 없는 HTTP 경계, 실제 실행 `REVISION`, 서비스 상태, 로그인 후 읽기 화면은 각각 별도 증거로 확인한다. 화면 스모크 테스트에서 배차 확정·완료·자원 변경은 실행하지 않는다.

배포 조건이 확인되지 않으면 검증된 후보와 미충족 조건을 기록하고 운영 상태를 변경하지 않는다.
