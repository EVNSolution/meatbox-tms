# 운영 UI와 기존 기능 이관 완료 범위

2026-10-06, Asia/Seoul. 이 문서는 기존 기능의 이관 경계와 이번 코드 검증을 기록한다. 특정 서버의 배포 성공은 해당 GitHub 실행과 배포 후 runtime·인증 화면 증거로 별도 확인한다.

## 현재 제품 경계

- 프런트는 `apps/web/` 한 모듈이다. 배차 관리, 배송 관제, 자원 관리와 별도 인증·디자인 가이드 진입점을 빌드한다.
- Kotlin/Spring이 인증, 준비된 원본 조회, SQLite 자원 저장, 날짜별 계산·확정·수정·순서 변경과 checkpoint를 소유한다.
- 웹 게이트웨이는 인증된 정적 파일과 Kotlin API 전달을 담당한다. TEST native 모드에서 Node 업무 writer를 시작하지 않는다.
- 배차 화면의 명령은 `calculate_dispatch`, `reassign`, `publish_dispatch`, `begin_dispatch_revision`, `cancel_dispatch_revision`, `set_route_order` 여섯 개다. 계산안, 확정 배차와 수정안을 구분한다.

## UI 정리 결과

공통 `components.css`가 버튼·입력·카드·탭·대화상자의 기본 표현을 소유한다. 일반 조작은 44px·6px 반경, 카드는 8px 반경이다. 자원 표의 조밀한 선택기는 기존 예외를 유지한다. 날짜 집계는 툴바 중앙에 정렬한다.

자료가 없는 날짜에도 배차·관제의 카드와 지도 영역을 유지한다. 자료 없음은 상단에서 잠시 표시한다. 자원 조회 중·실패에서도 표와 작업 영역을 유지하고 수량을 미확인으로 표시한다. 실제 빈 등록부만 0이며 검색 결과 없음과 구분한다. 장애 후 저장은 차단하며 재조회에서 임시 변경을 검토·복구한다.

서버에서 거부하던 안내 발송과 보류·복원 조작을 제거했다. 기존 알림과 보류 기록 조회는 유지한다. 제공되지 않은 고객 전달 결과를 성공으로 표시하지 않는다.

운영 연결과 원본 변환은 `operations-client.mjs`와 `operations-adapter.mjs`로 분리했다. 제품은 실제 `sourceData` 계약만 받는다. 원본 golden 비교 코드는 기존 Node 비교 트리에 보존한다. 화면 연결, 각 업무 DOM, 순수 모델, API client, 날짜, 지도와 알림은 [책임별 파일](project-structure.md)에서 수정한다.

도달할 수 없는 배송 검토·누적 배송지 DOM 모듈, 이전 관제·단말·고객 미리보기 CSS와 6,739,336바이트의 중복 글꼴을 제거했다. 현재 자원 화면은 승인된 차량·지역 코드 관리 범위를 유지한다. 누적 배송지 읽기 API는 유지한다. 폰트는 `/portal-font.ttf`와 기존 OFL 고지를 사용한다. 최초 출처와 삭제·추가 이력은 `fork-inventory.json`에서 보존한다.

## 날짜와 검증 경계

URL 날짜와 raw/gzip 본문의 날짜가 일치해야 한다. 날짜 누락·불일치·16 MiB 초과는 `DISPATCH_DATA_INVALID`로 거부한다. warm cache에서도 raw 날짜를 다시 확인한다. 잘못된 원본으로 상태를 반환하거나 checkpoint를 작성하지 않는다. 정상 원본의 바이트, 미지 필드와 ETag는 유지한다.

로컬 UI 검증 서버는 빌드한 API JAR의 임시 사본을 사용한다. 검증 중 다시 빌드해도 실행 중인 후보가 바뀌지 않으며 같은 fixture의 재시작도 같은 사본을 사용한다.

로컬 검증: Kotlin check·detekt·bootJar 75개, 프런트 230개, 산출물 4개, 루트 266개, 최종 실제 JAR 54개가 통과했다. 출처 검사 7개는 루트 검사에도 포함된다. 독립 코드 검토의 미해결 지적은 없다.

인증된 합성 브라우저에서 계산·확정·배송 순서 저장과 ETA 반영, 자원 코드 추가·변경·차량 저장·재조회, 등록부 장애의 미확인·재조회 복구를 확인했다. 320px에서 가로 넘침 없이 일반 입력 44px/16px 글꼴과 경로 버튼 44px를 확인했다. 디자인 가이드의 ETA·고객 카드 표본을 유지했다. 합성 시험은 실제 기사 수신·외부 알림 전달의 증거가 아니다.

## 새 제품 개발에 필요한 계약

기존 UI와 Kotlin 이관 범위는 위 경계다. 다음 항목은 삭제된 데모의 복원이 아니라 새 제품 기능이다.

- Meatbox 주문·기사 공급 API 또는 파일 인수의 인증·버전·재전송 계약
- SaaS 테넌트·역할과 주문·차량·고객별 접근 권한
- 실제 기사 GPS·사진·배차 수신·수락·오프라인 처리
- 실제 고객 알림 공급자·수신 결과와 지원배차의 호출·수락 정책
- QA·운영 환경의 구성과 승격 증거

후속 기준은 [운영 준비도](production-readiness.md), 사용법은 [운영 가이드](operator-guide.md), 변경 전달은 [CI·배포 기준](delivery-workflow.md)을 따른다.
