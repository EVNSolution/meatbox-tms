# 모바일 화면의 운영 범위

상태: 2026-09-29 현행 화면 판단. 이 문서는 모바일 전용 기능의 출시 승인이 아니라 현재 화면의 위치와 승격 조건을 정합니다.

## 결정

운영 메뉴는 기기가 아니라 업무로 나눕니다. 별도 **모바일** 탭을 만들지 않고, 작은 화면에서 필요한 관제 조회는 기존 **배송 관제** 안에서 다룹니다. 고객·배송원 화면은 현재 내부 검토용 직행 링크를 유지하되 운영 메뉴나 실제 사용자 서비스로 안내하지 않습니다. 기존 URL은 검토와 호환을 위해 유지합니다.

| 화면 | 지금의 목적 | 운영 화면으로 승격할 때 필요한 것 |
|---|---|---|
| 운영자의 좁은 화면 | 기존 배차·관제·자원 화면의 반응형 확인 | 현장·당직 사용 사례가 확인되면 배송 관제의 핵심 상태와 사건 확인부터 같은 경로에 제공. 현장 변경 액션은 권한·충돌·기기 검증 뒤 결정 |
| 고객 화면 | 선택 주문의 상태·안내 표현 검토 | 고객 본인에게 허용된 주문만 조회하는 서버 권한, 주문 단위 진입, 실제 위치·ETA의 출처, 외부 안내 전달 검증. 전체 매장 검색은 고객용 진입 방식이 아님 |
| 배송원 화면 | 배차·지도·도착·완료 흐름 검토 및 내부 상태 확인 | 로그인 배송원과 차량·배차의 서버 연결, 타인 자원 접근 거부, 명령 감사와 증빙 영속화, 실제 기기·전달 확인. 현재 화면의 차량 선택기는 검토 도구 |

배송원 화면 안의 **배송 / 지도**는 실제 배송 업무에도 의미가 있는 화면 내부 이동입니다. **과거 배차**는 원본 배정 자료를 보여 주는 조회이며 근무 시간·배송 완료 이력의 증거가 아닙니다. 예시 기록은 예시라고 표시합니다.

## 현재 안전 경계

- 서버는 로그인 여부만 확인하며 운영자·배송원·고객과 주문·차량·매장의 관계를 검사하지 않습니다. URL의 주문·차량 ID는 권한이 아닙니다. [운영 전환 기준](production-readiness.md)의 principal-resource authorization이 먼저 필요합니다.
- 고객 화면의 일부 시나리오는 화면 안 미리보기입니다. 배송원 화면의 도착·완료·순서 등 일부 조작과 시나리오 명령은 공유 서버 상태를 바꿀 수 있습니다. 따라서 검토 화면이라는 이름이 읽기 전용을 뜻하지 않습니다.
- `전체 배차 전송` 이후 배송원 화면을 열어 상태를 확인하는 것은 웹 반영 확인입니다. 실제 기사 앱 전달·수락 확인과 구분합니다.

## 적용·확인 계획

1. 제품 화면과 로컬 디자인 가이드에서 고객·배송원 화면을 **내부 검토용**으로 표시하고, 배송원 화면의 원본 배정 자료를 **과거 배차**로 부릅니다.
2. 기존 직행 URL과 운영 업무 메뉴 3개를 유지합니다. 고객·배송원 검토 링크를 실제 사용자용 서비스 링크로 소개하지 않습니다.
3. 좁은 화면의 운영 관제는 기존 경로의 읽기·선택·오류 상태로 확인합니다. 별도 모바일 메뉴나 샘플 수치를 만들지 않습니다.
4. 실제 고객·배송원 출시 판단은 서버 자원 권한, 증빙·전달 계약, 기기 검증을 통과한 뒤 별도 제품 변경으로 진행합니다.
