# 운영 업무 가이드

배차 준비부터 확정·배송 관제·자원 관리까지의 업무 흐름을 안내합니다. 실제 운영 권한·계정 발급 범위는 [보안 문서](security-and-access.md)를 따릅니다. 화면을 볼 수 있다는 사실만으로 해당 고객·차량에 대한 권한이 제한되어 있는 것은 아닙니다.

## 화면을 열었을 때

로그인하면 **배차 관리**가 먼저 열립니다. 왼쪽 메뉴에서 **배차 관리 → 배송 관제 → 자원 관리**로 이동합니다. 작은 화면에서도 같은 세 화면을 사용합니다. 고객·배송원·시나리오 데모 화면은 삭제됐습니다.

배차·관제의 날짜와 수량은 같은 툴바에서 확인합니다. 기본값은 서울의 실제 오늘입니다. 과거 날짜를 조회할 수 있지만 변경할 수는 없습니다. 자원 등록부는 날짜 선택과 독립적입니다.

자료가 없어도 카드·표·지도 컨테이너는 유지합니다. 확인된 빈 자료만 수량을 0으로 표시합니다. 로딩·조회 오류에서는 수량을 미확인으로 표시합니다. 긴 자료 없음 안내는 화면 상단에 잠시 표시한 뒤 닫습니다. 조회 오류와 재시도 조작은 화면에 남습니다.

## 배차를 준비하고 확정하기

1. **배차 관리**에서 대상 날짜와 주문·박스 집계를 확인합니다. 후보 배송원 패널의 후보 그룹은 실제 고용·차량 신원 확인 결과가 아닙니다.
2. **배송원 선택 및 배차**에서 후보를 선택하고 **배차 계산**을 누릅니다.
3. 계산안의 차량별 배정과 전체 수량을 확인합니다. 필요하면 지도에서 배송지 묶음을 선택해 핀배차를 조정합니다. 같은 이름·주소의 묶음은 함께 이동합니다.
4. 검토가 끝나면 **전체 배차 전송**을 누릅니다. 서버의 성공 응답 후 **배송 관제**에서 같은 날짜와 차량의 확정 배차를 확인합니다.

**전체 배차 전송**은 서버의 배차 확정을 뜻합니다. 실제 기사 앱 전달·수신·수락은 별도 연결이 필요합니다.

지도는 처음에 **권역 단위**로 열립니다. 권역에 마우스를 올리면 그 권역이 떠오르고, 옆에 해당 날짜의 **착지 수와 박스 수**(예: `12 Stop`, `48 box`)와 주문 수·배송원이 나타납니다. 터치 화면에서는 권역을 누르면 같은 정보가 보입니다. 개별 배송지를 보고 선택하거나 핀배차할 때는 **주문 단위**로 바꾸면 등록된 모든 주문 핀이 보입니다.

### 권역별 물량과 권역 선택

지도 아래 **권역별 물량** 표는 주문이 있는 권역마다 착지·박스·주문·중량을 보여 줍니다. 박스가 많은 권역부터 정렬하고 50곳씩 나눠 보여 줍니다.

- **착지**는 같은 이름·주소의 주문 묶음 하나입니다. 주문 건수와 다릅니다.
- 여러 권역에 걸친 주문은 권역마다 한 번씩 세므로 권역 합계가 전체 합계보다 클 수 있습니다. 권역을 알 수 없는 주문은 표 위 설명에 건수와 박스로 따로 표시합니다.
- **중량**은 원본 주문에 중량 값이 있을 때만 합산합니다. 값이 없으면 `미수신`으로 표시하며 추정값을 넣지 않습니다. 현재 공급되는 원본 파일에는 중량이 없습니다.
- 표의 권역을 누르거나 지도에서 권역을 누르면 그 권역의 경계가 강조되고 권역 안의 모든 배송지 핀이 함께 보입니다. 같은 권역을 다시 누르면 해제됩니다. 주문 단위 보기에서 권역을 누르면 권역 단위로 돌아옵니다.
- 핀을 누르면 배송지 정보 팝업에 이름·주소, 같은 배송지의 주문 수와 박스, 중량, 배송원, 권역, 주문번호가 나옵니다. 계산안이나 수정안이면 팝업에서 바로 **핀배차**를 열 수 있습니다.
- 지도에서 권역 밖의 빈 곳을 누르면 권역 선택이 해제됩니다.

### 타 권역으로 이관하기

권역 표의 **배송원** 열은 그 권역 안의 주문을 현재 가진 배송원을 박스가 많은 순서로 보여 줍니다. 배차 계산 전에는 `배차 전`입니다. 따로 저장한 권역-배송원 지정표는 없으며, 현재 배정에서 계산한 값입니다.

핀 팝업의 **타 권역 이관**은 그 배송지 묶음(같은 이름·주소)을 다른 권역을 맡은 배송원에게 재배정합니다.

1. 팝업에서 **타 권역 이관**을 누르고 **대상 권역**을 고릅니다. 지금 권역과, 넘길 다른 후보 배송원이 없는 권역은 목록에 없습니다.
2. 그 권역의 배송원이 박스 많은 순서로 나오며 가장 많은 사람이 미리 선택됩니다. 필요하면 바꿉니다.
3. 미리보기에서 이동 전후 수량을 확인하고 **배차 적용**을 누릅니다.

이관해도 배송지의 위치와 권역 소속은 바뀌지 않고 담당 배송원만 바뀝니다. 계산안·수정안에서만 가능하며 진행 및 완료 묶음은 이관할 수 없습니다. 배송 원본에는 권역-배송원 지정이 없어서 이 동작은 기존 핀배차와 같은 서버 명령(`reassign`)을 사용합니다.

### 여러 배송지를 한 번에 이관하기

계산안 또는 수정안에서 **복수 선택**을 켜면 지도가 주문 단위로 바뀌고, 지도 이동은 잠시 꺼집니다.

- 핀을 클릭하면 그 배송지 묶음의 주문이 모두 선택되고 다시 클릭하면 해제됩니다. 주문 목록 항목도 같은 방식으로 고를 수 있습니다.
- 지도를 드래그하면 사각형 안의 핀이 선택에 더해집니다. 마우스 버튼을 지도 밖이나 지도 위 안내 상자에서 놓아도 됩니다.
- 진행 중이거나 완료된 배송지 묶음은 선택되지 않고 "진행 및 완료 N곳은 제외"로 표시됩니다.
- **선택 이관**에서 대상 차량을 고르면 선택한 곳 수, 주문 건수, 박스, 이동할 건수가 미리 보입니다. 이미 대상 차량에 있는 주문은 이동에 포함되지 않습니다. 모두 이미 그 차량에 있으면 적용할 수 없습니다.
- 이관은 한 번의 서버 명령으로 처리되며 성공하면 선택이 비워집니다. 실패하면 선택이 유지됩니다. 배차를 확정한 뒤, 읽기 전용 날짜, 날짜 변경에서는 복수 선택을 쓸 수 없고 선택도 사라집니다.
- 지도를 옮기려면 **복수 선택**을 다시 눌러 끕니다. 선택은 끈 뒤에도 유지되어 **선택 이관**을 쓸 수 있습니다.

계산안을 만들었다는 이유만으로 배송원에게 배차가 확정되지 않습니다. 실패·응답 지연이 있으면 현재 상태를 다시 조회해 확정 여부를 확인한 뒤 처리합니다. 무조건 반복 전송하지 않습니다.

## 확정 배차를 조정하기

**배차 수정**을 누르면 별도 수정안으로 들어갑니다. 수정안 편집 중에는 기존 확정 배차가 계속 유효합니다. 변경 사항을 검토하고 **변경 배차 다시 전송**으로 확정하거나 **수정 취소**로 초안을 버립니다.

현재 진행 및 완료 주문을 포함한 보호 묶음은 임의로 재배정하지 않습니다. 기존 기록에서 같은 배송지가 여러 차량에 나뉜 충돌이 있다면 수정이 차단될 수 있습니다. 원본·체크포인트를 직접 편집해 우회하지 말고 [운영 절차](operations.md)로 원인을 확인합니다.

## 배송을 관제하기

**배송 관제**에서 날짜를 확인하고 차량을 선택합니다. 잔여 배송지·박스·제공된 예상 시간을 비교하고 우측에서 배송지별 상세와 기록을 확인합니다. 특정 과거 배송지를 펼친 것과 차량의 현재 목적지를 혼동하지 않습니다.

**배송 관리 → 배송 순서 관리**에서 변경안을 만든 뒤 저장합니다. 저장 전에는 확정 순서가 바뀌지 않습니다. 배송 중·완료·보류 행은 고정됩니다. 다른 사용자의 변경으로 충돌하면 새 상태를 읽고 다시 검토합니다. 기존 보류 상태는 조회하며, 이 화면에서 보류·복원을 변경하지 않습니다.

**배송 관리**에서 기존 처리 이력과 고객 알림 기록을 조회합니다. 이 화면은 새 고객 알림을 발송하지 않습니다. 기록 조회는 SMS·알림톡·앱 푸시 수신을 증명하지 않습니다. 지도 좌표와 제공된 예상 시간도 실제 기기 GPS·실측 ETA 수신을 증명하지 않습니다.

**배송 구분과 권역별 물량 (배차 관리)**: 배차 화면의 **배송 구분 (화면 표시 기준)**에서 전체/신선/택배를 고르면 지도·권역별 물량·차량 목록이 그 구분의 주문만 보여 줍니다. 구분은 미트박스 주문(`deliveryType`)에만 있어서 준비된 CSV 날짜에서는 선택기가 꺼지고 "원본(CSV)에는 배송 구분이 없다"고 알립니다. 배차 계산과 전송은 구분과 관계없이 전체 주문 기준입니다. 온도 구간(냉동/냉장) 필터는 아직 없습니다. 주문에 그 정보가 없습니다.

**권역별 물량** 표는 권역마다 착지(같은 이름·주소 묶음)·박스·주문 건수·중량·배송원을 보여 줍니다. 중량은 주문의 품목 중량(`items[].weightKg`)을 더한 값입니다. 한 품목이라도 없으면 그 권역은 "미수신"이고, 표 아래에 이유를 적습니다(CSV 원본에는 중량이 없음). 미트박스 주문은 권역 정보 없이 들어오므로 주소 좌표(`lat/lng`)가 있으면 화면이 권역 폴리곤으로 권역을 계산하고("권역 N건은 좌표로 화면에서 계산했습니다"), 좌표가 없는 주문은 권역에 들어가지 못했다고 알립니다. 권역을 고르면 그 권역의 경계와 속한 주문의 핀이 지도에 함께 나오고 핀을 누르면 배송지 정보(수량·중량·배송원·권역·주문번호)가 열립니다.

**배송 권역 (자원 관리)**: 자원 관리 맨 아래 "배송 권역"에서 권역 폴리곤을 직접 관리합니다. **GeoJSON 파일을 고르거나 내용을 붙여넣고** "현재 권역에 추가"(같은 코드는 덮어씀) 또는 "전체 교체"를 정한 뒤 **목록에 반영**을 누르면 목록에만 들어가고, **저장**해야 적용됩니다. 이름은 표에서 바로 고치고, 권역은 **삭제**로 지웁니다. 변경한 줄은 파란 배경이고 **변경 취소**로 되돌립니다. 코드(`zoneId`)는 고칠 수 없습니다. 코드가 없는 권역은 R1, R2…가 붙습니다. 저장하면 지도와 권역별 물량에 새로 고침 없이 적용되고, **준비된 권역으로 되돌리기**(두 번 눌러야 실행)로 처음 상태로 돌아갑니다. 닫힌 Polygon/MultiPolygon(경도·위도)만 가져올 수 있고 최대 500개, 꼭짓점 20만 개입니다. 준비된 CSV 날짜의 주문은 원래 권역 코드를 갖고 있어 지운 권역의 주문은 "권역 없음"으로 보이고, 새 권역에는 미트박스 주문(좌표가 있는 것)만 들어갑니다.

**운영 현황 (네 번째 메뉴)**: 기간(최대 31일)을 골라 조회하면 세 표가 나옵니다.
- **배송량**: 일별·주별(월요일 시작)·월별 주문·박스·착지·착지당 박스·운행 차량·완료 박스. 일별은 날마다, 주별·월별은 그 합입니다.
- **차량별 운행**: 날짜·차량마다 출발·마지막 도착·완료 시각, 운행 시간(출발부터 마지막 착지를 닫을 때까지, 분), 추정 거리, 착지 완료/전체, 박스 완료/전체, 착지당 박스, 착지당 분. 아직 진행 중인 차량은 완료·운행 시간이 비어 있습니다.
- **권역별 현황**: 권역마다 주문·박스·착지. 권역을 알 수 없는 주문(미트박스 주문 등)은 표에 들어가지 않고 건수를 따로 알립니다.
- **운행 거리는 추정입니다.** 직선거리에 우회 계수를 곱한 값이고, 실제 주행 거리는 서버가 받지 않아 미수신입니다. 기사 표시는 지금 기준의 배정입니다.
- **일일 목표 초과 추가 수수료**: 규칙 파일(`incentive-rules.json`)이 있으면 표에 인원수와 금액 열이 생깁니다. 규칙(목표·단가·기준)은 표 위에 한 줄로 나옵니다. 파일이 없거나 깨졌으면 계산하지 않았다고 알립니다. 규칙 바꾸는 법은 운영 런북의 "추가 수수료 규칙 교체"입니다. 지난 날짜도 지금 규칙으로 다시 계산됩니다.

**기사 기준정보 (자원 관리)**: 자원 관리 화면 아래 "기사 기준정보"에서 기사 계정마다 권역·숙련도·연락처·주소·계약정보·차종·탑 사양과 최대 Capa(착지수·Box 수량·중량)를 등록합니다. 기사 행의 **수정**을 누르면 입력칸이 열리고 **저장**하면 바로 적용됩니다. 모든 칸을 비우고 저장하면 그 기사의 기준정보가 삭제됩니다. 비워 둔 Capa는 "미설정"입니다. 연락처·주소·계약정보는 개인정보라 운영자 계정만 볼 수 있고, 계약 종료 때의 데이터 내보내기 파일에 들어갑니다.

**Capa 초과 점검 (배차 관리)**: 배차가 확정(또는 수정안)이면 배차 화면 위쪽에 "Capa 초과 배송원 N명"이 나옵니다. 차량의 착지수·박스·중량 합을 그 차량에 배정된 기사의 최대 Capa와 비교합니다(같으면 초과가 아님). **초과 배송원 보기**를 누르면 목록이 열리고, 행을 누르면 그 차량이 선택되고 지도가 그 차량의 주요 권역(박스가 가장 많은 권역)으로 이동합니다. 배차를 전송하면 초과가 있을 때 목록이 저절로 열립니다. Capa를 설정하지 않았거나 기사가 배정되지 않은 차량은 점검하지 못한 것으로 따로 알립니다. 중량이 없는 주문(CSV 원본 등)이 있으면 그 차량의 중량은 비교하지 못했다고 알립니다. 이 점검은 알리기만 하며 배차 전송을 막지 않습니다.

**기사 특이사항**: 배송 관제의 기록 탭 아래 "기사 특이사항"을 열면 선택한 날짜에 기사가 완료·미배송 때 남긴 메모를 최신순으로 보여 줍니다(배송지·결과·미배송 사유·기사·주소·시각). 메모가 없는 완료는 나오지 않습니다. 운영자 계정만 볼 수 있고, 날짜별 이벤트 기록의 상한을 넘은 오래된 이벤트는 빠질 수 있습니다.

**기사 알림**: 배차 전송·수정 재전송·재배정·순서 변경으로 어느 차량의 경로가 바뀌면 결과 안내에 "기사 알림 발송 N대"가 나옵니다. 푸시를 요청했을 뿐 기기 수신은 확인하지 못합니다(기사 앱은 다시 열 때 최신 경로를 읽습니다). 서버에 푸시 설정이 없으면 "기사 알림 발송 0대. 푸시 설정이 없어 보내지 않았습니다"가 나옵니다.

**위치와 전체 차량 지도**: 한 대를 보는 지도의 차량 마커는 "기사 앱 위치 · 3분 전"처럼 출처와 갱신 시각을 말합니다. 기사 앱 위치가 없으면 "기준 위치"(GPS가 아님)로 나옵니다. 지도의 **전체 차량**을 켜면 위치가 있는 모든 차량을 한 지도에서 봅니다. 이름이 붙은 아이콘은 기사 앱 위치(선명), 오래된 위치(10분 넘게 갱신 없음, 흐림), 기준 위치(더 흐림)를 구분하고 온도가 범위 밖이면 빛이 붙습니다. 아이콘이나 목록의 차량을 누르면 카드에 위치 출처·시각, 온도, 현재 배송지, 남은 배송지·박스가 나오고 **배송 정보 보기**(한 대 보기로 복귀)와 **온도 이력**(온도 탭)을 누를 수 있습니다. 위치가 없는 차량은 지도에 나오지 않고 개수만 알립니다.

**온도**: 서버가 받은 차량 온도를 관제에서 확인합니다. 값은 색이 아니라 문구와 함께 표시됩니다.

- 차량 행·운행 요약·지도 차량 마커에 현재 온도와 상태가 나옵니다: **범위 밖**(연속 3개 측정이 허용 범위를 벗어남), **미수신**(설정 시간 동안 새 값이 없음), **정상**. 값을 보낸 적이 없는 차량이나 오늘이 아닌 날짜에는 표시가 없습니다. 범위 밖이면서 값이 오래된 차량은 범위 밖으로 표시합니다.
- 정렬에서 **온도 이상 우선**을 고르면 범위 밖, 미수신, 정상, 정보 없음 순으로 보입니다.
- 지도의 **온도 현황**은 모든 차량의 현재값·마지막 수신·허용 범위를 한 표로 보여 줍니다. 선택한 날짜와 관계없이 지금 값이고 30초마다 갱신됩니다. 차량 이름을 누르면 그 차량의 온도 탭이 열립니다.
- **온도** 탭(관제 위 탭, 주소 `#/control/temperature`)은 선택 차량의 현재값과 선택 날짜 하루의 1분 평균 선 그래프를 보여 줍니다. 최저·최고 띠, 허용 범위선, 센서별 선을 그리고 5분 넘게 받지 못한 구간은 이어 그리지 않고 비워 둡니다. 선 위에 포인터를 올리거나 좌우 방향키로 값을 읽습니다. 오늘 이력은 탭이 열려 있는 동안 60초마다 갱신됩니다.
- "온도 수신이 설정되지 않은 환경입니다"라고 나오면 그 환경에는 온도 수신이 없습니다. 값이 없는 것과 구분합니다. 허용 범위는 화면에서 바꾸지 않고 서버의 `ranges.json`으로 관리합니다([운영](operations.md)).

**ETA**: 기사 앱에서 출발이 처리되면 서버가 계산한 도착 예정 시각이 배송지 상세와 운행 상세에 "(서버 계산)"으로 나옵니다. 운행 상세 아래에 출발 시각(기기/서버 시각), 재산출 횟수와 사유를 적습니다. 출발 전에는 계획 추정치이고 그 사실을 안내합니다. 출발 처리는 기사 앱에서 하고, ETA 계산 설정은 서버 환경 변수입니다. 웹은 표시와 관리(순서 변경)를 합니다. 직선거리 모델이라 실제 도로와 다를 수 있습니다.

**지원배차**는 차량 정보를 검토하는 화면입니다. 차량 호출·수락·재배정은 연결되지 않았습니다.

## 자원 등록부 관리하기

**자원 관리**는 차량 표 한 개와 **지역 코드 관리** 패널을 제공합니다.

실제 차량·기사 명부가 아직 없어, 배차·관제·자원 화면의 차량번호는 모두 날짜 CSV의 기사 표기 그룹에서 만든 표시값이고 **(미검증)**으로 표시합니다. 기사 이름과 권역은 CSV 원본값입니다. 번호판과 위치 문구만 만든 값입니다. 실제 차량 등록은 준비 중입니다.

- 차량번호·지역 코드·기사 이름으로 검색하고 지정/미지정 상태를 필터링합니다.
- 각 차량의 선택기에서 등록된 코드 또는 미지정을 선택합니다. 한 코드에 여러 차량을 연결할 수 있습니다.
- 차량별 임시 변경을 검토한 뒤 저장합니다. 코드 관리와 차량 배정 편집의 잠금 안내를 따릅니다.
- 코드를 추가하거나 이름을 바꾸려면 지역 코드 관리 패널을 사용합니다. 코드 이름 변경은 그 코드를 참조하는 등록부 차량에도 반영됩니다.
- 저장 후 새로고침하여 값이 유지되는지 확인합니다. 충돌 시 최신 등록부와 자신의 변경을 다시 비교합니다.

**기사 배정**: 표의 **기사** 열에서 차량마다 담당 기사 계정을 고릅니다. 기사 계정은 [운영](operations.md)의 기사 초대 절차로 먼저 만들어야 합니다(없으면 안내가 나옵니다).

- 다른 기사를 고르면 **바로 저장**되고 "저장됨. 기사 앱에 바로 적용됩니다."가 나옵니다. 지역 코드처럼 임시 변경으로 모아 저장하지 않습니다.
- **미배정**(해제)을 고르면 먼저 "기사 앱에서 이 차량을 바로 볼 수 없게 됩니다" 확인이 나오고, **해제 확인**을 눌러야 저장됩니다. 취소하면 아무것도 바뀌지 않습니다.
- 다른 사람이 먼저 바꿨다면 자동으로 덮어쓰지 않고 최신 배정을 다시 불러와 알려 줍니다. 확인한 뒤 다시 고릅니다.
- 비활성 계정이나 없는 계정이 배정돼 있으면 선택기에 "(비활성 계정)"·"(계정 없음)"으로 표시하고 경고합니다. 다른 기사에게 배정하거나 해제합니다.
- 기사 배정을 읽지 못하면 열은 "미확인"이고 지역 코드 편집은 계속 됩니다. "이 환경에는 기사 배정 기능이 없습니다"는 Node 소유 구성의 안내입니다.
- 좁은 화면에서는 표가 상자 안에서 좌우로 스크롤됩니다.

등록부의 코드 변경은 일별 배차를 재계산하거나 주문을 재배정하지 않습니다. 조회 중이거나 실패하면 검색·편집을 막고 집계를 미확인으로 표시합니다. 표와 저장 영역은 유지합니다. 초기 DB 설정·이행은 별도 운영 작업입니다. [자원 DB 점검 주의사항](operations.md)을 먼저 확인합니다.

## 현재 운영 범위

제품 화면은 배차 관리·배송 관제·자원 관리 세 개입니다. 로그인·등록은 Kotlin 인증을 사용하고 디자인 가이드는 참조 화면입니다.

고객·배송원 제품, 배송 사진 업로드, 실제 GPS 입력과 외부 알림 발송은 현재 제공하지 않습니다. 해당 기능은 사용자 신원·권한과 공급자 계약을 확정한 뒤 개발합니다. [운영 준비도](production-readiness.md)에 필요한 조건을 기록합니다.

## 문제가 있을 때

| 증상 | 먼저 할 일 |
|---|---|
| 오늘 주문이 없음 | 서울 날짜와 선택 날짜, 해당 날짜 자료 존재를 확인. 과거 날짜를 오늘로 바꾸지 않음 |
| 오래된 상태·충돌 | 새 상태를 다시 조회하고 변경을 재검토 |
| 로그인이 풀림 | 재인증 후 대상 날짜·배차를 다시 확인 |
| 저장 실패 | 성공으로 간주하지 말고 최신 상태와 오류 코드를 확인 |
| 등록부 오류 | 비어 있음으로 간주하지 말고 담당자에게 설정·스키마 확인 요청 |
| 재시작 후 상태가 다름 | 추가 변경을 멈추고 릴리스·저장 설정·체크포인트 복원 결과 확인 |

운영 담당자에게 전달할 정보는 발생 시각(KST), 화면과 날짜, 수행한 동작, 오류 코드, 마지막 정상 확인 시각입니다. 고객 주소·전화번호·계정·쿠키·사진 원문은 공유 기록에서 제거합니다. [장애 기록 양식](templates/incident-record.md)을 사용할 수 있습니다.
