# 운영 업무 가이드

배차 준비부터 확정·배송 관제·자원 관리까지의 업무 흐름을 안내합니다. 실제 운영 권한·계정 발급 범위는 [보안 문서](security-and-access.md)를 따릅니다. 화면을 볼 수 있다는 사실만으로 해당 고객·차량에 대한 권한이 제한되어 있는 것은 아닙니다.

## 화면을 열었을 때

로그인 후 왼쪽 메뉴에서 **배차 관리 → 배송 관제 → 자원 관리**로 이동합니다. 공통 헤더에는 전역 날짜나 뷰어 전환이 없습니다. 모바일이라는 별도 운영 메뉴도 없습니다. 작은 화면에서 관제할 때는 같은 **배송 관제**로 들어갑니다. 고객·배송원 직행 링크는 내부 검토 화면이며 실제 사용자용 접근 경로가 아닙니다. [모바일 화면의 운영 범위](mobile-surface-policy.md)를 따릅니다.

배차·관제의 날짜와 수량은 같은 툴바에서 확인합니다. 기본값은 서울의 실제 오늘이며 자료가 없으면 빈 상태입니다. 과거 날짜를 명시적으로 조회할 수 있지만 변경할 수는 없습니다. 자원 등록부는 날짜 선택과 독립적입니다.

## 배차를 준비하고 확정하기

1. **배차 관리**에서 대상 날짜와 주문·박스·후보 차량 집계를 확인합니다. 후보 그룹은 실제 고용·차량 신원 확인 결과가 아닙니다.
2. **배송원 선택·배차**에서 후보를 선택하고 **배차 계산**을 누릅니다.
3. 계산안의 차량별 배정과 전체 수량을 확인합니다. 필요하면 지도에서 배송지 묶음을 선택해 핀배차를 조정합니다. 같은 이름·주소의 묶음은 함께 이동합니다.
4. 검토가 끝나면 **전체 배차 전송**을 누릅니다. 서버의 성공 응답 후 확정 배차가 배송원·관제에 반영되는지 확인합니다.
5. 고객·배송원 검토 링크에서 같은 날짜와 대상을 다시 확인합니다. 이 확인은 웹 상태 반영의 증거이며 외부 기사 앱 전달·수락의 증거는 아닙니다.

계산안을 만들었다는 이유만으로 배송원에게 배차가 확정되지 않습니다. 실패·응답 지연이 있으면 현재 상태를 다시 조회해 확정 여부를 확인한 뒤 처리합니다. 무조건 반복 전송하지 않습니다.

## 확정 배차를 조정하기

**배차 수정**을 누르면 별도 수정안으로 들어갑니다. 수정안 편집 중에는 기존 확정 배차가 계속 유효합니다. 변경 사항을 검토하고 **변경 배차 다시 전송**으로 확정하거나 **수정 취소**로 초안을 버립니다.

현재 진행·완료 주문을 포함한 보호 묶음은 임의로 재배정하지 않습니다. 기존 기록에서 같은 배송지가 여러 차량에 나뉜 충돌이 있다면 수정이 차단될 수 있습니다. 원본·체크포인트를 직접 편집해 우회하지 말고 [운영 절차](operations.md)로 원인을 확인합니다.

## 배송을 관제하기

**배송 관제**에서 날짜를 확인하고 차량을 선택합니다. 잔여 배송지·박스·제공된 예상 시간을 비교하고 우측에서 배송지별 상세와 기록을 확인합니다. 특정 과거 배송지를 펼친 것과 차량의 현재 목적지를 혼동하지 않습니다.

순서 편집은 변경안을 만든 뒤 저장합니다. 저장 전에는 확정 순서가 바뀌지 않으며, 진행·완료 상태의 보호 조건과 최신 상태 일치 검사가 적용됩니다. 다른 사용자의 변경으로 충돌하면 새 상태를 읽고 다시 검토합니다. 보류는 완료가 아니며 잔여 업무와 구분해 봅니다.

고객 안내와 배송 팁은 시스템 내부 기록입니다. 안내를 저장했다는 이유로 SMS·알림톡·앱 푸시가 발송되었다고 설명하지 않습니다. 지도 차량 위치·예상 시간도 실제 GPS와 측정 ETA인지, 계획·시연 값인지 구분해야 합니다.

## 자원 등록부 관리하기

**자원 관리**는 차량 표 한 개와 **지역 코드 관리** 패널을 제공합니다.

- 차량번호·지역 코드로 검색하고 지정/미지정 상태를 필터링합니다.
- 각 차량의 선택기에서 등록된 코드 또는 미지정을 선택합니다. 한 코드에 여러 차량을 연결할 수 있습니다.
- 차량별 임시 변경을 검토한 뒤 저장합니다. 코드 관리와 차량 배정 편집의 잠금 안내를 따릅니다.
- 코드를 추가하거나 이름을 바꾸려면 지역 코드 관리 패널을 사용합니다. 코드 이름 변경은 그 코드를 참조하는 등록부 차량에도 반영됩니다.
- 저장 후 새로고침하여 값이 유지되는지 확인합니다. 충돌 시 최신 등록부와 자신의 변경을 다시 비교합니다.

등록부의 코드 변경은 일별 배차 재계산·주문 재배정·지도 권역 경계 변경이 아닙니다. 연결 오류를 ‘등록 차량 0대’로 해석하지 않습니다. 특히 초기 DB 설정·이행은 별도 운영 작업이며 화면을 확인하기 전에 [자원 DB 점검 주의사항](operations.md)을 확인해야 합니다.

## 고객·배송원 화면을 해석하기

| 화면 | 확인할 내용 | 보증하지 않는 것 |
|---|---|---|
| 배송원 배차 | 날짜·차량과 서버에서 확정한 배차 | 해당 로그인 사용자가 실제 기사라는 신원 확인 |
| 도착·완료 | 대상 배송지, 필수 요청 체크와 완료 응답 | 브라우저 사진이 서버에 영구 보관되었다는 증거 |
| 배송원 과거 배차 | 선택 날짜의 원본 기사 그룹별 주문·박스 | 실제 근무 시작/종료·실제 배송완료 이력 |
| 고객 조회 | 선택 주문의 상태와 예상 시간 | 고객별 서버 조회 권한 격리 |
| 고객 페이지 시연 | 해당 페이지 안의 표시 미리보기 | 실제 위치 이동·운영 배차 변경·외부 알림 발송 |

현재 사진 확인에는 예시 이미지를 사용하는 촬영 경로와 선택 파일의 임시 미리보기 경로가 있습니다. ‘사진 촬영’ 버튼이 실제 카메라 촬영·서버 업로드를 보증하지 않습니다.

**시연 버튼의 범위를 구분하세요.** 고객 페이지의 로컬 미리보기와 달리, 운영·배송원에서 서버 명령으로 전달되는 장면 변경은 공유 상태를 바꿀 수 있습니다. 실제 자료를 사용하는 화면에서 단순 설명용으로 누르지 않습니다. `/scenario/*` 원본 시나리오와 날짜별 운영은 별도 상태입니다.

## 문제가 있을 때

| 증상 | 먼저 할 일 |
|---|---|
| 오늘 주문이 없음 | 서울 날짜와 선택 날짜, 해당 날짜 자료 존재를 확인. 과거 날짜를 오늘로 바꾸지 않음 |
| 오래된 상태·충돌 | 새 상태를 다시 조회하고 변경을 재검토 |
| 로그인이 풀림 | 재인증 후 대상 날짜·배차를 다시 확인 |
| 저장 실패 | 성공으로 간주하지 말고 최신 상태와 오류 코드를 확인 |
| 등록부 오류 | 비어 있음으로 간주하지 말고 담당자에게 설정·스키마 확인 요청 |
| 재시작 후 상태가 다름 | 추가 변경을 멈추고 릴리스·저장 설정·체크포인트 복원 결과 확인 |

운영 담당자에게 전달할 정보는 발생 시각(KST), 화면과 날짜, 수행한 동작, 오류 코드, 마지막 정상 확인 시각입니다. 고객 주소·전화번호·계정·쿠키·사진 원문은 공유 기록에서 제거합니다. [장애 기록 양식](templates/incident-record.md)을 사용할 수 있습니다.
