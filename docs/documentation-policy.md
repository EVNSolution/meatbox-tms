# 문서 관리 기준

문서는 담당자가 시스템을 이해하고 같은 절차로 업무를 수행할 수 있게 하는 안내입니다. 문서도 코드와 함께 Git으로 관리하며, 해당 소스 버전의 문서는 같은 커밋이나 태그에서 확인합니다.

## 갱신 원칙

**배포할 때마다 README의 버전이나 날짜를 바꾸지 않습니다.** 기능·계약·설정·절차가 달라질 때 해당 설명을 같은 변경에 포함합니다.

| 문서 종류 | 담을 내용 | 갱신 시점 |
|---|---|---|
| README·문서 안내 | 제품 목적, 시작 방법, 코드·문서 길잡이 | 목적·진입점·실행 방법이 달라질 때 |
| 설계·API·업무·운영 참조 | 동작, 입력·출력, 책임, 제약, 수행 절차 | 설명하는 기능이나 계약이 달라질 때 |
| 릴리스·장애·검증 기록 | 대상 SHA, 실행 환경, 시각, 결과, 담당, 복구 근거 | 해당 작업마다 새 기록 작성 |
| 과거 결정·시험 자료 | 당시의 배경과 근거 | 원문 보존. 수정이 필요하면 후속 기록으로 연결 |

참조 문서에는 수동으로 맞춰야 하는 ‘기준 SHA’, ‘최종 갱신일’, 특정 배포의 테스트 수·성공 여부를 반복하지 않습니다. Git 변경 이력이 문서와 코드의 버전 관계를 관리합니다. 런타임 요구 버전과 데이터 스키마 버전은 동작 계약이므로 필요한 위치에 유지합니다.

같은 코드의 재배포·환경별 승격은 참조 문서의 갱신 사유가 아닙니다. 적용 SHA·환경·검증 결과는 [릴리스 기록](templates/release-record.md)에 남깁니다. 예제의 고정 날짜는 입력 형식을 설명하는 예시임을 명시하고, ‘오늘’이나 최신 결과로 취급하지 않습니다.

## 근거를 표시하는 방법

| 표현 | 필요한 근거 | 그것만으로 증명되지 않는 것 |
|---|---|---|
| 코드에 구현됨 | 커밋과 실제 파일·기호 | 운영 활성화, 사용자 사용 가능 |
| 로컬 검증됨 | 커밋·런타임·명령·결과·시험 자료 종류 | 운영 데이터 호환, 서버 성능 |
| 서버 반영됨 | 실제 릴리스 경로·버전·설정·헬스 결과 | 업무 데이터 정합성, 브라우저 동작 |
| 업무 흐름 확인됨 | 날짜·역할·환경·상태 전후·브라우저 결과 | 타 기기·다른 고객·대규모 부하 |
| 기기 수신 확인됨 | 송신 사건과 실제 기기 수신·동작의 연결 | 모든 기기·모든 망의 전달 보장 |
| 미확인 | 필요한 증거와 확인 방법 | 없음으로 간주할 근거 |

`0건`은 조회가 성공했고 대상 범위를 모두 확인한 경우에만 씁니다. 오류·미연결·미조회는 미확인입니다. 예시 데이터는 실제 직원·고객·운행 이력으로 바꾸어 서술하지 않습니다.

## 정보별 기준 문서

- 현재 진입 경로·개요: [README](../README.md), [문서 안내](README.md).
- 상태·저장 책임: [도메인](domain-and-state.md), [아키텍처](architecture.md).
- 경로·요청 계약: [API](api-reference.md). 전체 코드를 복제하지 말고 검증 대상과 오류를 설명합니다.
- 데이터 준비: [날짜 자료](dated-dispatch-data.md). 개인정보 원본·실제 주문 샘플을 문서에 붙이지 않습니다.
- 화면 규칙: [DESIGN](../DESIGN.md). 변천사는 이력 문서에 둡니다.
- 실행·복구: [개발](development.md), [운영](operations.md). 기본값과 필수 설정, 읽기와 쓰기 부작용을 구분합니다.
- 검증·남은 과제: [검증](verification.md), [운영 전환](production-readiness.md). 계획을 구현 현황으로 승격하려면 근거가 필요합니다.

같은 계약을 여러 문서에 길게 복사하지 않습니다. 안내 문서에는 결론과 링크만 두고, 세부 계약은 위 기준 문서에서 관리합니다.

## 변경에 따른 갱신

| 변경 | 함께 갱신할 문서 |
|---|---|
| 같은 코드 재배포·환경별 승격 | 릴리스 기록만 작성. 참조 문서 버전·날짜 변경 없음 |
| 배차 상태·명령·동시성 | 도메인, API, 관련 검증 항목, 업무 가이드 |
| 저장 형식·스키마·데이터 출처 | 아키텍처, 날짜 자료, 운영 복구·롤백, 릴리스 기록 |
| 환경 변수·배포 방식 | 개발, 운영, 보안, 릴리스 기록 |
| 메뉴·날짜·버튼·빈 상태 | DESIGN, 업무 가이드, 관련 브라우저 검증 |
| 인증·리소스 권한 | 보안, API, 운영 전환 기준, 권한 회귀 테스트 |
| 기기·외부 연동 | 아키텍처, API, 운영 전환 기준, 실환경 검증 기록 |

문서 변경자는 사실과 코드를 대조하고, 검토자는 따라 실행할 때의 부작용·누락·오해를 확인합니다. 특정 개인을 임의로 운영 책임자로 지정하지 않습니다. 릴리스·장애 기록에는 실제 담당 역할과 확인자를 적습니다.

## 완료 확인

- 참조 문서는 관련 구현·계약과 일치하며, 배포별 SHA·시각·결과는 별도 기록에 있습니다.
- 상대 링크가 존재하고, 명령·환경 변수·API가 코드와 일치합니다.
- 새 파일을 추가했다면 문서 안내에서 찾을 수 있습니다.
- 시험 계정·쿠키·키·주문·주소·DB 덤프를 포함하지 않습니다.
- 과거 기록은 당시 시점 그대로 보존하며 현행 문서로 연결합니다.
- 테스트 수·처리량·차량 수는 특정 측정 기록에만 둡니다. README의 제품 보증 수치로 복사하지 않습니다.

형식의 정돈만으로는 완료가 아닙니다. 특히 ‘조회’가 데이터 이행을 유발할 수 있는 코드처럼, 실제 부작용까지 확인해야 합니다. 현재 사례는 [자원 DB 운영 절차](operations.md)를 참고하세요.
