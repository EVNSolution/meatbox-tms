# 로그인·배차 저장의 Kotlin 이관

2026-10-05, Asia/Seoul. 앞 단계에서 Kotlin 원본 조회·자원 저장과 새 프런트를 TEST에 연결했다. 이번 단계는 남은 로그인·세션과 **실제 운영 배차 명령 6종**의 실행 소유자를 Kotlin으로 옮긴다.

## 범위와 소유자

- 인증: 기존 계정·초대 JSON v1, scrypt 비밀번호, 로그인·등록·로그아웃·세션, 정확한 Origin·쿠키·속도 제한. 새 비밀번호를 요구하거나 기존 계정을 재발급하지 않는다. 세션은 현재와 같이 프로세스 수명에 귀속되며 전환·재시작 때 재로그인한다.
- 배차: 계산, 배송지 묶음의 핀배차, 확정, 수정안 생성·취소, 배송 순서 저장. 날짜·원본 ID·boot·revision, 같은 배송지 유지, 진행·완료 배송지 보호, 저장 실패 시 상태 불변을 보존한다.
- 기존 schema-v2 배차 checkpoint와 그 안의 확정 운행 기록은 검증 후 복원한다. 실제 확정 기록을 초기화하거나 새로운 계산안으로 덮어쓰지 않는다.
- 과거 기사·고객·시나리오 데모와 전용 명령은 새 제품의 이관 대상에서 제외한다. 기존 이력의 위치·이벤트·진행 상태를 읽는 것과 데모 변경 API를 새로 제공하는 것은 구분한다.
- 계정 변경에는 기존 파일 잠금·원자적 저장을 유지한다. 배차는 날짜별 직렬화·후보 상태·파일 동기화·원자적 교체 뒤 성공을 반환한다. 한 자료의 writer는 하나다.

## 파일 책임

Kotlin은 `auth/`의 비밀번호·계정 저장·세션·요청 처리, `dispatch/`의 계산·계획·기록 복원·날짜 저장·요청 처리로 나눈다. 프런트와 게이트웨이는 실행 소유자만 선택한다. 혼합 기간에 Node 배차가 남아 있어도 세션은 지정한 인증 소유자에게 확인하며, Kotlin 인증이 Node 자신에게 되돌아가는 순환 호출을 만들지 않는다.

## 완료와 검증

1. 현재 테스트를 회귀 기준으로 삼고 합성 자료의 Node golden 응답·checkpoint를 고정한다. 실제 JAR에서 계정 호환, 세션·Origin·크기·속도 제한, 6종 명령, 날짜·boot·revision 충돌, 묶음·진행 보호, 동시 저장·실패·재시작을 확인한다.
2. Kotlin check·detekt·bootJar, 프런트 타입·lint·빌드·연결 검사, 기존 Node 회귀 검사를 통과한다. 입력 검증을 줄여 lint를 통과시키지 않는다.
3. TEST 실제 계정·checkpoint는 백업과 해시·revision을 확보하고 복사본에서 읽기·복원·저장을 검증한다. 공개 전환은 검토를 거친 같은 릴리스로 수행한다.
4. 공개 로그인·조회·보호 자산, 실제 확정 기록 보존, 코드 롤백·재적용·서비스 재시작을 확인한다. 실제 업무 변경을 검증용으로 실행하지 않는다. 임시 계정·비밀번호·쿠키·접속 키는 정리한다.

QA·운영 환경 생성, 실제 주문 공급자·GPS·사진·알림, 테넌트·역할별 권한은 이번 호환 이관으로 구현됐다고 판단하지 않는다. 과거 데모 실행과 원본 복구 릴리스의 보존은 새 업무 API의 소유권과 별도로 관리한다.
