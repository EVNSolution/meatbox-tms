# 미트박스 TMS 데모 — 설계 문서

날짜: 2026-09-13
목적: 미트박스 TMS 제안 문서의 「고객 배송 트래킹」 + 「다이나믹 ETA」 요구사항을 고객사 앞에서 시연하기 위한 인터랙티브 웹 데모.

## 데모 시나리오

가락 MFC에서 출고된 전용차 1대(적재 70박스)가 서울 송파·강남 일대 8개 정차지를 순회 배송한다.
주인공 고객은 **5번째 정차지의 식당**. 발표자는 관제 화면에서 시나리오를 시작/배속 조절하고,
"교통사고 발생", "정차 지연"을 주입하거나 기사 앱에서 배송 순서를 변경하면
고객 화면의 ETA가 즉시 재계산되고 알림이 표시된다.

## 아키텍처

Node 서버 1개(Express + ws)가 시뮬레이션 상태를 소유하고, 3개 화면이 WebSocket으로 구독한다.
여러 기기(노트북 + 폰)에서 동시 접속 가능. EC2(3.36.96.156)에 배포하여 원격 시연.

### 서버
- `src/route-data.js` — 정차지 좌표 + 정차지 쌍별 실제 도로 polyline/거리/시간 (OSRM에서 미리 생성해 하드코딩, 런타임 외부 API 의존 없음)
- `src/simulation.js` — 시뮬레이션 엔진: 1초 틱, 배속(1x/5x/20x), 차량 이동, 정차지 도착 시 스캔 이벤트 자동 발생 → 상태 전환, 하차 서비스타임
- `src/eta.js` — ETA 엔진: 남은 구간 이동시간(교통 계수 반영) + 중간 정차지 서비스타임. 시간 범위로 표시하며 진행될수록 범위 축소. 재계산 트리거: 순서 변경 / 교통 이슈 / 정차 지연. ETA 변동 폭이 10분 초과면 고객 알림 발생.
- `server.js` — Express 정적 서빙 + WebSocket 브로드캐스트 + 컨트롤 명령 처리

### 화면 (빌드 없는 vanilla JS + Leaflet/OSM CDN)
- `/customer` (모바일 프레임): 주문 상세, 9단계 상태 타임라인(주문 접수→결제 완료→피킹 중→라벨 부착→상차 대기→배송 출발→N번째 순서 배송 예정→인근 배송 중→배송 완료), ETA 카드("13:00~14:00 도착 예정"), 지도 위 차량 위치, 앱 푸시 배너 + 카카오 알림톡 모형, ETA 변경 안내
- `/driver` (모바일 프레임): 배송 리스트(정차지별 박스 수), 순서 변경 버튼(핵심 트리거), 하차 완료 스캔 버튼, 현재 목적지 요약
- `/control` (데스크톱): 전체 지도 + 차량/경로/정차지 현황, KPI(적재율/완료·잔여 착지/ETA 정확도), 이벤트 로그, 발표자 컨트롤(시작/리셋, 배속, 교통사고 주입, 정차 지연 주입)

## 상태 플로우 (고객 노출)

주문 접수 → 결제 완료 → 피킹 중 → 라벨 부착 → 상차 대기 → 배송 출발 → X번째 순서 배송 예정 → 인근 배송 중 → 배송 완료
- 출고 전 단계는 시나리오 시작 시 압축 재생, 배송 출발부터 차량 이동과 연동
- 상태 전환은 구간별 스캔 이벤트(시뮬레이션)로 자동 처리

## ETA 로직 (데모용)

- leg 이동시간: OSRM 기준 시간 × 교통 계수(기본 1.0, 사고 주입 시 해당 leg 상향)
- 정차지 서비스타임: 4분(하차·검수)
- ETA 창: 출발 전 ±30분 → 배송 중 ±20분 → 3정차지 이내 ±10분 → 인근 배송 중 ±5분
- 재계산 트리거 시 즉시 브로드캐스트, 변동 10분 초과 시 "배송 예정 시간이 변경되었습니다" 알림

## 테스트

- ETA 엔진 핵심 로직만 `node:test` 단위 테스트, 화면은 브라우저 시연으로 검증
