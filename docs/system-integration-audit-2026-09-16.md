# 백엔드·운영 웹·배송원·고객 연결 점검

> **이력·검토 자료.** 아래 내용은 작성 당시의 계획·판정·시험 결과입니다. 수량·구현 상태·배포 여부를 현재 상태로 해석하지 않습니다. 현행 계약과 절차는 [문서 안내](README.md), 후속 전환 조건은 [운영 전환 기준](production-readiness.md)을 사용합니다.

최초 점검 기준: 2026-09-16, `codex/system-integration-audit`. 기준 코드는 당시 미병합 PR #25의 `119eeb1`이며, 이미 구현된 80대 운영·파일 체크포인트를 포함한다. 아래 점검 내용과 427개 테스트는 최초 로컬 수정 시점의 기록이다. 이후 사용자의 배포 요청에 따라 기존 배차 보존 호환 패치를 추가하고 429개 테스트를 통과한 뒤 `549f13b`를 배포했다. 실제 보존·재시작·공개 화면 검증은 [배포 기록](deployment-2026-09-16-integration.md)을 참조한다.

## 판단

백엔드와 세 웹 화면의 기본 흐름은 연결되어 있다. 그러나 현재 계정은 모두 검토자이고, 배송원 앱은 모바일 웹 뷰어다. **실제 기사·고객에게 각자의 권한으로 제공하는 서비스**로 전환하려면 접근 범위, 증빙, 수신 확인, 내구성 있는 이력과 외부 연동을 추가해야 한다.

현재 구현을 버리고 프런트를 다시 만드는 것보다, 이미 있는 배차·배송 상태를 하나의 운영 기준으로 유지하면서 서버의 책임을 채우는 순서가 적절하다. 이번 조정은 기존 화면 구성을 유지하고 재현된 연결 결함을 수정했다.

## 실서비스 전환에 남은 빈틈

P0는 실제 기사·고객 접근을 열기 전에 필요한 경계다. P1은 현장 운영의 신뢰성을 완성하는 연결이다. 구현 의사결정을 위한 우선순위이며 이번에 완성했다는 뜻은 아니다.

| 순위 | 현재 코드에서 확인한 상태 | 필요한 연결과 완료 기준 |
| --- | --- | --- |
| P0 계정과 데이터 범위 | `publicUser`는 사용자명·표시명·생성일만 반환. 인증된 검토자는 같은 날짜 전체 주문을 읽고 다른 차량의 명령도 실행 가능 | 운영자·기사·고객을 구분하고 서버에서 기사↔배차, 고객↔주문 소속 검사. 다른 사용자의 ID로 조회/명령/실시간 구독을 시도하면 거절되어야 함. 초안 정보도 서버 응답에서 역할별로 제한 |

## 다음 구현 단위와 수용 조건

1. **사용자 한 명의 전체 흐름**: 운영자가 기사 A에게 확정 → 기사 A가 자기 배송만 조회 → 고객 A가 자기 주문만 조회. 기사 B/고객 B의 접근 거절과 초안 비노출을 서버 수준에서 증명한다. 기존 검토자 계정은 명시적으로 이전하고 새 계정의 권한을 암묵적으로 올리지 않는다.
2. **증빙이 남는 배송 완료**: 사진 업로드 → 서버 증빙 ID → 필수 요청 확인 → 완료 이벤트를 원자적으로 기록한다. 업로드 실패·중복 완료·재시작에도 동일 주문과 사진 관계가 남아야 한다.
3. **끊겨도 복구되는 기사 작업**: 확정 배차 수신/수락과 명령 ID를 연결한다. 재전송은 같은 결과를 돌려주고 완료 알림을 두 번 만들지 않아야 한다. 현재의 boot/revision 충돌 검사와 함께 동작해야 한다.
4. **실제 입출력 연결**: 확정된 주문 공급자, 위치 수신, 알림 공급자를 각각 붙인다. 공급자가 확인되지 않은 단계는 로컬 결과를 실운영 증거로 보고하지 않는다.
5. **안전한 릴리스**: 백업과 기존 확정 배차·진행 이력 보존을 확인하고, 새 버전에서 복원 및 실제 계정별 연동을 검증한다. 현재 운영의 155대 확정 배차를 80대 계획으로 자동 교체하지 않는다.

## 검증 기록

- 변경 전 기준 코드: 기존 Node 테스트 416개 통과. 그 위에서 통신 수명·링크·위치 회귀를 실패로 재현한 뒤 수정했다.
- 변경 후 전체 테스트: Node v22.23.2와 v26.3.1에서 각각 427개 통과, 실패 0.
- 독립 코드 리뷰: 변경 코드/테스트 9개 파일에서 실행 가능한 추가 결함 없음. 문서와 운영 배포는 리뷰 대상과 분리했다.
- 변경 JavaScript 구문 검사와 `git diff --check` 통과. 별도 lint/typecheck 명령은 이 저장소에 정의되어 있지 않다.
- [system-integration.test.mjs](../test/system-integration.test.mjs)는 실제 인증 HTTP 서버, 독립 검토자 계정 3개, 합성 원자료, 날짜별 저장 디렉터리를 사용한다. 역할별 권한 검증을 대신하는 테스트는 아니다.
- 통합 회귀: 미배차 → 계산안 → 확정 → 배송 시작 → 도착 → 동일 목적지 두 주문의 묶음 완료. 운영/배송원/고객의 주문 ID·박스 합계·상태·알림·좌표를 대조한다. 오래된 revision의 중복 완료를 409로 거절하고, 서버 재시작·재로그인 후 동일 상태 복원을 확인한다.
- 로컬 브라우저: `127.0.0.1:3056`의 합성 주문 3건/배송지 2곳/12박스. 계산안 상태의 기사 화면은 확정 배차 없음, 확정 후 2곳/12박스, 사진 및 필수 요청 확인 후 완료 1곳/잔여 7박스를 표시했다. 관제도 완료 1곳, 고객은 두 주문 합계 5박스와 출발·도착·완료 이력을 표시했다.
- 브라우저에서 링크 수정 후 고객이 선택한 `QA1`과 날짜가 운영/기사 링크에 유지되고, 실제 운영 뷰어 이동 후에도 해당 완료 배송지가 펼쳐지는 것을 확인했다. 고객 화면에서 수집된 콘솔 error/warn은 없었다.
- UI 배치 변경, 설치 앱 검증, 실기기 GPS, 사진 영구 저장, 외부 알림 전달, 실제 운영 배포는 이번 검증에 포함되지 않는다.

```sh
node --test test/system-integration.test.mjs
node --test apps/combined/source-client.test.mjs apps/combined/simulation-client.test.mjs apps/combined/delivery-review.test.mjs test/source-operations.test.mjs
```
