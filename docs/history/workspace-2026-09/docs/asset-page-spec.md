# 디자인 가이드 · Asset Page 명세

> **초기 디자인·정적 데모 이력.** 이 문서는 현재 구현·운영 서버의 상태를 나타내지 않습니다. [현행 저장소 문서](../../../README.md)를 먼저 사용하세요. 원문은 당시 판단의 근거로 보존합니다.

2026-09-29: 로컬 디자인 가이드의 화면 구성 절은 현행 [제품 DESIGN.md](../../../../DESIGN.md)의 메뉴와 44px 날짜 조작·별도 상태/집계 영역을 보여 줍니다. 아래 2026-09-14 메뉴 계약은 당시의 정적 데모 이력입니다.

확정된 메뉴 표시명은 **디자인 가이드**입니다. 업무 메뉴 세 개 아래의 검토용 메뉴에 두며, 제작 순서는 [메뉴 구성과 다음 작업](menu-plan.md)을 따릅니다.

같은 UI 요소의 크기·내용·상태를 나란히 비교하는 작업 공간의 명세입니다. 현재 로컬 미리보기의 `#/design`에 **공식 자산 기반 디자인 가이드**가 구현되어 있으며, [관제 페이지](terminal-view.md)와 같은 공통 표현을 사용합니다. 아래 전체 카탈로그의 모든 변형·오류·접근성 상태가 완성된 것은 아닙니다.

2026-09-13 사용자가 **B안 · 운영 밀도 중심**을 선택했습니다. 색·타이포·간격과 기본 UI는 [design.md의 승인 기준](../design.md)을 따릅니다. 목록과 사건 이력의 가독성, 절제된 강조색, 작은 모서리를 기준으로 개별 요소를 검토합니다. 시각 방향의 승인이 아래 모든 요소의 상태·정책·규격을 일괄 확정한 것은 아닙니다.

이 명세는 임지인님의 UI/UX 디자인 레퍼런스·아키텍처 영역입니다. 박상현님의 B&W 시나리오 구현과는 [입출력 경계](architecture.md)를 맞춥니다. 컴포넌트 표본은 합의한 데이터로 먼저 준비할 수 있으며, 실제 외부 시스템 연결을 요구하지 않습니다.

2026-09-14 개정: 상단 **운영 뷰어 / 고객 뷰어 / 배송원 뷰어**, 좌측 **주문 관리 / 배송 목록 / 배송 관제**. 배송 관제 우측 탭에 **배송 관리**를 배치합니다. 가이드의 첫 절에서 같은 구성을 확인할 수 있습니다. 현행 시각 값과 메뉴 계약은 [design.md](../design.md)가 우선합니다.

## 검토 순서

1. 브랜드·타이포·색·간격의 후보와 출처를 확인합니다.
2. 버튼·입력·필터·표·패널 같은 기본 UI를 검토합니다.
3. 배송 단계·ETA·이력·안내 요소의 정상·변경·미확정 상태를 준비합니다.
4. 검토된 요소로 운영 목록의 한 행, 배송 상세, 고객 카드의 작은 조합을 확인합니다.
5. 검토한 공통 표현을 운영 뷰어의 배송 목록·배송 관제와 고객·배송원 뷰어에서 같이 사용합니다.

## 배송·ETA 카탈로그

| D01 | 배송 단계 배지 | 원문 9개 표현 중 데모에서 단계로 분류한 7개, 미확인 | 원문 명칭을 보존하고 색·아이콘은 디자인 제안으로 적용. 순서·인근 정보는 별도 | T2-02 |

| D07 | 변경 사유 | 순서 변경, 교통 지연, 정차 지연, 사유 없음 | 확인된 합성 사건만 설명. 원인 추정 문구 없음 | T3-04 |

시나리오 선택·사건 실행은 조회 필터와 구별한 시연 컨트롤입니다. Config는 허용된 표기·선택 값을 공급하고, UI는 기능·알고리즘을 다시 구현하지 않습니다. 필요한 입력·결과 데이터 예시는 C08 상세 패널을 활용하며 별도 API 관리 화면은 추가하지 않습니다.

컴포넌트 이름은 제작 목록을 식별하기 위한 이름입니다. 컴포넌트 파일명·프레임워크·Props를 결정한 것은 아닙니다.

## 한 표본에 같이 남길 정보

- 요소 이름과 목적
- 참고한 R1~R5 또는 원문 T2/T3 요구 ID
- 관측한 부분과 데모를 위해 바꾼 부분
- 허용 상태, 필수 텍스트, 미확정 값 표시
- 시나리오에서 받을 데이터와 UI에서 발생시키는 허용 동작. 필터·표기 변경과 도메인 동작의 구분
- 운영용·고객용 차이와 좁은 폭에서의 동작
- 남은 질문 및 검토 상태: 미착수 / 검토 중 / 준비됨

현재 첫 버전은 B안의 주 액션·브랜드 강조·작업 영역·구분선, 타이포·간격, 기본 조작 요소, 공통 ETA의 기본·변경·미확정·갱신 실패·완료, 사건 이력·알림·고객 카드 표본을 포함합니다. 운영 뷰어의 배송 목록·배송 관제와 고객·배송원 뷰어와 `view-components.mjs`의 공통 ETA·배지·알림·고객 카드 표현을 재사용합니다.

이 범위는 아래 전체 19개 C01~C10·D01~D09 카탈로그 정책을 모두 구현하거나 승인한 상태가 아닙니다. 특히 처리 중·오류·정렬·긴 내용·모든 배송 단계와 변경 조합·대비 판정은 남아 있습니다.

## 작은 조합 세 가지

| 조합 | 포함 요소 | 보여줄 내용 |
|---|---|---|
| 운영 목록 1행 | C07, D01, D03, D04, D05 | 가상 배송 ID → 현재 상태 → ETA → 변화 → 갱신 시각 |
| 배송 상세 | C08, D02, D04, D06, D07, D08 | 현재 진행, 변경 이력, 알림 문구 |
| 고객 카드 | C10, D09, D03, D08 | 시연 표식, 도착 예정 범위, 배송 진행, 고객 안내 문구 |

현재 로컬 UI는 이 조합의 공통 표현을 세 업무 화면에 적용했습니다. 새로운 지도 요소, 매출 차트, 차량·권역 분석 화면은 추가하지 않습니다.

## 확인 기준

현재 첫 버전의 기본 요소와 ETA·사건·알림·고객 카드 조합은 로컬 화면에 연결했습니다. Node 테스트 7개와 실제 브라우저의 메뉴·선택·필터·초기화·키보드·8개 시나리오 ETA 일치 확인은 [UI 검증 기록](ui-verification.md)을 따릅니다. 아직 구현하지 않은 카탈로그 상태와 실제 픽셀·대비 판정은 후속 검토로 남깁니다.
