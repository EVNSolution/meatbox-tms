## 2026-09-14 뷰어·업무 메뉴 개정 검증

- 상단 운영·고객·배송원 뷰어, 좌측 주문 관리·배송 목록·배송 관제와 하단 디자인 가이드의 표시·라우팅을 확인했습니다.
- DEMO-004 선택 후 배송원·고객 뷰어에서도 같은 배송과 마지막 ETA를 유지했습니다. 운영 뷰어는 마지막 배송 목록으로 복귀했습니다.
- 관제 가운데 알림 미리보기 선택과 우측 배송 관리·장치 표시 선택이 독립적으로 동작하고, 우측 방향키 이동에서 초점·선택·내용이 일치했습니다.

- 이 기록은 로컬 레퍼런스 검증입니다. Safari 직접 확인과 실제 배포·API 연결 증거는 포함하지 않습니다.

## 레이아웃

브라우저 확대율과 도구 설정값을 구별하기 위해 실제 `innerWidth`와 DOM 경계를 읽었습니다. 수치는 CSS px 기준입니다.

| 실제 폭 | 확인 결과 |
|---|---|
| 2000px | 배송 현황의 제목과 본문 시작 위치가 모두 x=265.99px. 수정 전 x=112px/266px 불일치 해소 |
| 1280px | 네 페이지 모두 문서 폭 1280px, 표시 페이지 1개, 중복 ID 없음. ETA·고객 카드·단말 ETA·패널·입력·선택 요소의 넘침 없음 |
| 390px | 네 페이지 모두 문서 폭 390px, 표시 페이지 1개, 중복 ID 없음. 위 요소의 넘침 없음. 좌측 메뉴는 72px 구조 유지 |

헤더 하단과 좌측 메뉴 시작점은 1280px에서 약 56px로 일치하며, 390px에서 각각 134.81px/135px로 맞습니다. 좁은 배송 표는 자체 가로 스크롤 영역을 사용해 열 정보를 유지합니다. 문서 전체를 가로로 이동할 필요는 없습니다.

넓은 배송 현황과 고객 보기·디자인 가이드, 좁은 가이드와 고객 화면, 펼친 시나리오 팝업을 스크린샷으로 검토했습니다. 좁은 팝업에서 8개 시나리오 버튼·초기화 버튼·초기화 설명이 화면 안에 보이는 것을 확인했습니다. 이는 DOM 경계 측정과 사람에 해당하는 시각 검토이며 기준 이미지와의 자동 픽셀 비교는 아닙니다.

시각 검토 기록은 `.omx/state/terminal-view/ralph-progress.json`에 남깁니다. 작성 중인 브라우저 검토 댓글은 변경하지 않았습니다.

## 디자인 가이드 주석 후속 검증

사용자 주석 1~6을 반영한 이번 검토는 디자인 가이드 한 페이지와 지적된 하단 메뉴 이름에 한정했습니다. 이전 가로 넘침 검사에서 놓친 내부 테두리를 수정했습니다. ETA 1열 정보의 오른쪽 테두리는 수정 전 1px/0px/1px로 번갈아 나타났으며, 수정 후 15개 항목 모두 오른쪽·아래 테두리 없이 항목 사이 수평선만 표시합니다.

제목과 짧은 메타 정보는 가이드 안에서 간격과 줄바꿈으로 구별합니다. 설명의 `발송·전달·수신`과 사용자가 좋다고 한 사건 이력의 내용·배치는 유지했습니다. 공통 렌더러의 데이터와 다른 업무 페이지의 기본 메타 표시는 유지하고, 하단 디자인 가이드 메뉴는 보조 문구와 두 줄 이름을 중앙에 정렬했습니다.

실제 1303px에서 ETA 카드·알림 정보·사건 이력·상단 기본 요소를 스크린샷으로 확인했습니다. 1100px·429px·390px에서도 문서 폭이 화면 폭과 일치하고 제목·카드·ETA·입력·메타 정보·메뉴 이름의 넘침은 없었습니다. 하단 메뉴 이름의 중심 오차는 0.004px 미만입니다. Node 7개 테스트와 변경 모듈의 문법 검사를 통과했습니다. 내부 선·여백·줄바꿈에 대한 이번 결과로 이전의 단순 넘침 중심 확인을 보완합니다.


## ETA 하단 여백의 구조 검증

후속 주석으로 앞선 검토의 누락을 확인했습니다. 1303px에서 카드 하단과 마지막 요소 사이 여백은 기본·변경 0px, 미확정 36px, 갱신 실패·완료 12px였습니다. 높이를 강제한 카드 안에서 자식 margin과 인접 카드의 내용 높이가 여백을 결정하던 구조였습니다.

디자인 가이드의 카드에 머리·유연한 본문·자연 높이 하단의 세 영역을 적용했습니다. 하단은 부모가 세로 12px·가로 14px padding과 12px gap을 소유하며 자식 바깥 margin은 0입니다. 같은 행의 높이 차이는 본문이 흡수합니다. 상태 이름의 높이를 빼는 `calc` 대신 부모의 5px gap으로 상태 이름과 카드를 배치합니다.

`.omx/qa/eta-card-spacing.cua.js`의 `verifyEtaCardSpacing(cdp)`를 실제 로컬 브라우저에서 실행했습니다. 1303px·1100px·390px의 다섯 상태, 총 15개 조합에서 위·아래 12px, 좌·우 14px, 두 요소 사이 12px를 확인했습니다. 기본·변경처럼 안내가 없는 경우도 마지막 요소 아래 12px를 유지합니다. 390px에서는 안내가 여러 줄로 늘어난 실제 배치와 문서 가로 넘침 부재도 확인했습니다. 이 검사는 CI에 연결된 브라우저 테스트가 아닌 Codex 브라우저 도구용 회귀 절차입니다.
