# 로컬 UI 레퍼런스 · 뷰어와 업무 메뉴

> **초기 디자인·정적 데모 이력.** 이 문서는 현재 구현·운영 서버의 상태를 나타내지 않습니다. [현행 저장소 문서](../../../README.md)를 먼저 사용하세요. 원문은 당시 판단의 근거로 보존합니다.

2026-09-29: 로컬 `#/design` 가이드의 메뉴 표본은 현행 [제품 DESIGN.md](../../../../DESIGN.md)에 맞춰 배차 관리·배송 관제·자원 관리와 고객·배송원 내부 검토 링크로 갱신했습니다. 별도 모바일 운영 탭은 없습니다. 아래 상단 뷰어·옛 업무 메뉴 설명은 2026-09-14 정적 데모의 이력입니다.

- 상태: 2026-09-14 사용자 지정 배포 기준의 상단 뷰어·좌측 업무 메뉴를 로컬 레퍼런스에 반영했습니다. 실제 배포 변경은 포함하지 않습니다.
- 디자인 기준: 승인된 B안. 후속 요청에 따라 빈 지도 미리보기를 펼칠 수 있습니다. 실제 지도 이미지·SDK·좌표·위치 추적·경로선은 없습니다.
- 목적: 차량별 TMS 장치를 선택하고 같은 배송 결과의 ETA·알림·사건 이력을 확인하는 운영 페이지입니다.
- 현재 실행: [로컬 미리보기](http://127.0.0.1:60016/#/design). 실행 중인 로컬 서버가 필요합니다.

## 페이지 구성

| 영역 | 표시와 동작 |
|---|---|
| 상단 뷰어 | 운영 뷰어 / 고객 뷰어 / 배송원 뷰어 |
| 좌측 운영 메뉴 | 주문 관리 `#/orders`, 배송 목록 `#/deliveries`, 배송 관제 `#/control`. 하단 디자인 가이드 `#/design`는 검토용 |
| 주문 관리 | 주문 데이터 연결 전의 명시적인 빈 목록 표본 |
| 배송 목록 | 합성 배송 목록의 검색·상태·ETA 변경 필터, 선택 배송 요약, 관제·고객 뷰어 이동 |
| 차량·단말 목록 | 가상 차량, TMS ID, 배송 ID, 단계, ETA, 마지막 갱신. 검색·상태 조건으로 조회 |
| 선택 단말 | 차량·배송·고객 별칭. 장치 연결 상태는 미확인 |
| ETA·배송 진행 | 시간 범위, 이전 값, 변경 사유, 계획 순서, 실제 도착 미확인 |
| 사건 이력 | 입력 사건 시각, 배송 단계와 ETA 변경 결과 |
| 알림 미리보기 | TMS 장치에 표시될 문구 예시와 고객 안내 예시를 구분. 실제 발송·전달·수신 상태 없음 |
| 관제 우측 배송 관리 | 가상 차량·단말·배송 관계, 실제 도착·완료의 별도 시각, 장치 연결·수신 미확인 |
| 관제 우측 장치 표시 | 차량 장착형 장치에 데이터를 배치한 표시 예시. 실제 장치 화면 캡처나 규격 재현 아님 |
| 고객 뷰어 | 선택 배송의 같은 ETA·상태·갱신 시각을 사용하는 상단 뷰어 |
| 배송원 뷰어 | 선택 차량·배송과 작업 정보를 표시하는 합성 표본. 실제 작업 처리 기능은 없음 |
| 디자인 가이드 | 상단·좌측 구성 계약, 공식 브랜드·컬러·타이포·Radius·기능 아이콘과 공통 배송 카드 상태 |
| 지도 미리보기 | 지도 펼치기 / 지도 접기. 펼친 영역에는 빈 미리보기라는 안내 문구만 표시 |
| 시나리오 패널 | 본문 밖의 공통 플로팅 레이어. 왼쪽 핸들로 이동, 접기/펼치기, TMS-001의 합성 결과 선택 및 출발 상태로 초기화 |

시나리오 패널은 `document.body`에 붙는 공통 모듈로 분리했습니다. 배송·관제·고객·배송원 화면의 상세 탭, 조회 결과, 스크롤과 독립적으로 남습니다. 주문 관리와 디자인 가이드에서는 숨깁니다. 같은 브라우저 탭에서 새로고침해도 패널 위치와 접힘 상태를 유지합니다. 왼쪽 핸들에 포커스한 뒤 방향키로 이동하거나 Home으로 우하단에 복원할 수 있고, Escape로 접을 수 있습니다.

## 표본과 초기화

- 기본 표본은 TMS-001의 S4 교통 지연입니다. ETA는 13:00~14:00에서 13:20~14:20으로 변경됩니다.
- S1~S7에서 인근·완료를 각각 선택할 수 있어 총 8개 표시 표본이 있습니다.
- 각 선택은 이전 분기를 누적하지 않고 완성된 표본 전체를 교체합니다. 초기화는 S2 출발로 돌아가며 조회 조건, 선택 단말, 상세 탭, 관제 우측 탭를 함께 초기화합니다.
- 상차 대기에서 ETA·순서는 미확정입니다. 갱신 실패에서는 마지막 ETA와 11:30 갱신을 유지하고 11:50 실패 표본을 별도로 표시합니다.
- 완료 표본은 완료 시각을 주 정보로 표시하며 실제 도착 시각은 미확인으로 남깁니다.
- 차량·단말·배송의 1:1 연결은 UI 표본 한정입니다. 실제 운영 관계는 확정되지 않았습니다.

## 구현 경계

원본은 `previews/terminal-view/`의 정적 HTML/CSS/JavaScript입니다. 패키지 설치나 제품 프레임워크 선정 없이 로컬 화면을 준비했습니다.

- `index.html`: 상단 뷰어·좌측 업무 메뉴와 여섯 hash route를 포함한 공통 셸.
- `styles.css`: B안 시각 기준과 반응형 배치.
- `app.mjs`: 화면 전환, 목록 선택, 공통 결과 표현, 탭, 조회 조건, 초기화.
- `view-model.mjs`: hash route와 합성 조회 결과의 필터·선택 경계.
- `view-components.mjs`: 배송 목록·관제·고객 뷰어·디자인 가이드가 공유하는 ETA·배지·알림·고객 카드 표현.
- `design-guide.mjs` / `design-guide.css`: 공식 자산·화면 구성 계약·공통 요소·ETA 상태를 비교하는 디자인 가이드.
- `scenario-tools.mjs` / `scenario-tools.css`: 페이지 본문 밖의 시나리오 패널, 드래그·키보드 이동, 화면 경계 보정, 위치와 접힘 상태 저장. 페이지는 시나리오 선택·초기화 동작을 전달합니다.
- `scenario-tools.test.mjs`: 이동·펼침·좁은 화면 전환 시 패널이 화면 안에 남는지 검증.
- `sample-data.mjs`: 합성 조회 결과와 조회 필터. 상태 전이·ETA 계산 알고리즘이 아니며 외부 API를 호출하지 않습니다.
- `sample-data.test.mjs`: 분기 독립성, 미확정·갱신 실패·완료 구별, 조회 불변성, 실제 장치 수신 증거 부재 검증.
- `view-model.test.mjs`: 메뉴별 선택 유지, 공통 조회 조건, 8개 표본의 공통 ETA 표현 검증.

상현님의 구현과 조합할 때에는 [UI 데이터 연결 명세](ui-data-contract.md)를 기준으로 합의된 조회 결과를 `view-model.mjs`의 데이터 공급 경계에 연결합니다. 현재 필드명은 UI 표본 형식이며 최종 API 계약이 아닙니다. TMS 장치의 규격·프로토콜·실제 연결·발송 정책은 미확정입니다.

## 실행과 확인

프로젝트 루트에서 다음 명령으로 표시할 수 있습니다. 같은 포트를 사용하는 미리보기가 실행 중이면 기존 서버를 그대로 사용합니다.

```sh
python3 -m http.server 60016 --bind 127.0.0.1 --directory previews/terminal-view
node --check previews/terminal-view/app.mjs
node --check previews/terminal-view/scenario-tools.mjs
node --test previews/terminal-view/*.test.mjs
```

2026-09-14 확인 결과: Node 테스트 8개와 JavaScript 문법 검사를 통과했습니다. 상단 뷰어 간 선택 배송 유지, 마지막 운영 업무 복원, 주문 미연결 빈 상태, 관제 두 탭 그룹의 독립 키보드 이동을 확인했습니다. 다음 문장은 2026-09-13의 기존 검증 범위입니다: 실제 브라우저에서 8개 시나리오의 관제·TMS·고객 ETA 일치와 메뉴·선택·브라우저 히스토리·필터·초기화·키보드·플로팅 팝업 회귀를 확인했습니다. 상세 절차와 검증 한계는 [UI 검증 기록](ui-verification.md)에 정리합니다.

이 검증은 로컬 합성 UI의 동작 증거입니다. 실제 장치·외부 API·상현님 시나리오 결과·알림 발송을 연결하거나 검증하지 않았습니다.
