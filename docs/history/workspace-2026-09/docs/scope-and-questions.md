# 담당 범위와 확인 질문

> **초기 디자인·정적 데모 이력.** 이 문서는 현재 구현·운영 서버의 상태를 나타내지 않습니다. [현행 저장소 문서](../../../README.md)를 먼저 사용하세요. 원문은 당시 판단의 근거로 보존합니다.

## 이번 작업의 결론

임지인님의 준비 범위는 **2번 고객 배송 트래킹과 3번 다이나믹 ETA의 UI/UX 디자인 레퍼런스와 아키텍처**입니다. UI 요소와 레퍼런스, 도메인 표현, API·데이터 접근·Config·필터의 책임을 먼저 정리합니다. 박상현님은 **시나리오 기반 B&W 기능·알고리즘 구현**을 담당합니다. 이 작업에서는 실제 시스템 개발이나 알고리즘 구현에 착수하지 않습니다.

사용자는 운영 화면 중심에 고객 미리보기를 함께 두는 구성을 확인했습니다. 데모 목표는 2026-09-16 수요일입니다. 인용 메일의 금요일 내부 취합과 계약서 제출일은 당시 업무 맥락이며, 이번 일정·제출·발송 지시로 실행하지 않습니다.

미트박스의 기존 배송 서비스·시스템·API 유무는 미확인입니다. 기존 시스템과 연결할 수 있게 하자는 설명은 설계 가능성의 예시입니다. 이번 준비는 [아키텍처](architecture.md)의 화면·시나리오·데이터 경계까지만 다루며, 별도 연동 플랫폼으로 확장하지 않습니다.

## 원문과 담당의 대응

근거: 첨부 역할 문서 (당시 로컬 첨부 문서. 저장소에 포함되지 않아 원문 접근은 별도 확인)의 「핵심 기능 및 세부 요구사항」과 사용자가 붙여 넣은 메일. DOCX의 목록 순서와 글자 색을 직접 확인했습니다.

| 원문 항목 | 원문이 요구하는 결과 | 이번 준비 작업 | 다른 담당·후속 범위 |
|---|---|---|---|
| 1. 권역 설정 최적화 | 물동량·차량 대수·적재·비효율 권역 분석 | 범위 경계를 이해하는 데만 참고 | 빨간 요청사항의 분석은 메일상 케빈님. 이번 UI 범위 밖 |
| 2. 고객 배송 트래킹 | 주문부터 문 앞 배송 완료까지 단계와 알림 제공 | 배송 상태, 타임라인, 순서, 알림 미리보기의 용어·UI 명세 | 스캔 자동 전환, 앱 푸시·알림톡 실제 연동 |
| 3. 배송 도착 예정 다이나믹 ETA | 배송 이력·예측·교통 상황으로 ETA를 계산·갱신 | 시간 범위, 변경 사유, 이전·현재 값, 미확정 표현, 시나리오와 맞출 입출력 | 이번 데모의 기능·알고리즘 구현은 박상현님. Data Mart·실모델·실시간 교통 연동은 현 단계 밖 |

메일에서 케빈님에게 배차·ETA 분석을, 지인님·상현님에게 전체 구현을 제안한 것은 원문 업무 배경입니다. 이번 데모의 역할은 사용자가 새로 정한 박상현님의 시나리오 구현, 임지인님의 UI/UX·아키텍처를 따릅니다. UPS는 메일의 향후 고려 사항이며 이 작업에서 기존 UPS 서비스를 변경하지 않습니다.

## 추가 데이터 요청 초안

RAW에는 배송완료 시각 등의 디테일이 부족해 보인다는 내용은 **메일 발신자의 관찰**입니다. 이번 작업에서 RAW의 실제 컬럼·누락률은 검증하지 않았습니다. 아래 자료는 추후 ETA 분석·연동을 위해 필요 여부를 확인할 목록입니다.

| 요청 정보 | 필요한 이유 | 이번 준비 단계의 취급 |
|---|---|---|
| 데이터 사전, 주문·배송·박스·착지의 가명 식별자와 관계 | 한 행의 의미 및 결합 기준 확인 | 실제 데이터 대신 필드 정의 요청 초안 |
| 출고·상차·출발·도착·완료 이벤트 시각과 시간대·이벤트 원천 | 상태 전환과 실제 도착/완료 구별 | 수집·적재하지 않음 |
| ETA 예측 생성 시각, 점 예측, 범위, 변경 사유, 변경 전후 이력 | 예측 시점별 평가와 고객 노출 재현 | 합성 예시로 대체 |
| 최초·변경된 배송 순서와 변경 시각, 정차 시작·종료 | 세 재계산 원인의 의미 확인 | UI 설명용 사건만 정의 |
| 실제 알림 정책과 익명화된 메시지 예시, 처리 단계 정의 | 요청·접수·전달·수신 상태 구별 | 메시지 미리보기만 준비 |

처음에는 개인정보가 제거된 데이터 사전과 소수의 익명 예시만으로 계약을 확인하는 방향을 제안합니다. 실제 고객명·주소·전화번호, 원본 주문 파일, 원시 위치 데이터는 이번 데모 준비에 필요하지 않습니다.

## 현 단계 완료 기준

- 2·3번 요구와 지인님 UI 역할, 알고리즘·연동 담당의 경계가 문서로 구분되어 있습니다.
- 운영 중심과 고객 미리보기 방향, 지도 완전 제외가 명시되어 있습니다.
- 레퍼런스 출처, Asset Page 목록, 도메인·시나리오, 미확정 질문이 있습니다.
- 원문 목표를 실측 성능으로 바꾸지 않았고, 실제 RAW나 외부 발송·배포를 사용하지 않았습니다.
