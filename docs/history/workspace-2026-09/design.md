## Brand

- 사용자가 “B 가 좋다.”라고 선택하여 **B안 · 운영 밀도 중심**을 후속 디자인 기준으로 확정했습니다. 최초 표시되었던 A안과 이전 추천은 승인 기준이 아닙니다.
- A: 브랜드 중심 — 밝은 표면, 관측 기반 자홍색 강조, 목록과 고객 안내의 균형.
- **B · 승인:** 좌측 세로 메뉴와 운영 밀도 중심 — 촘촘한 목록, 절제된 액션색, 목록·사건 이력 우선. 사용자가 **좌측 메뉴 탭 때문에 B안을 선택했다**고 명시했으므로 좌측 메뉴는 후속 화면에서도 유지해야 하는 핵심 구조입니다.
- C: ETA 중심 — 큰 시간 표현, 넉넉한 여백, 변경 사유 우선.
- [후보 원본](/Users/jiin/.codex/visualizations/2026/09/13/01a0996f-8c05-74f3-891e-5bbc6a79e7cd/meatbox-design-options.html)은 대화용 시안입니다. 실제 Asset Page·제품 페이지·재사용 컴포넌트가 아닙니다. 모든 안이 같은 합성 표본을 쓰며, 미확정·완료·ETA 변경 표현을 비교합니다.

## Product goals

- 운영 담당자가 배송 목록에서 현재 상태와 ETA 변경 건을 찾고, 상세 이력과 고객 노출 내용을 확인하게 합니다.
- 고객은 도착 예정 시간 범위, 배송 진행 상태, 변경 안내를 이해할 수 있어야 합니다.
- 먼저 Asset Page에서 공통 UI의 모양·용어·상태를 검토하고, 그 요소를 미리보기 화면에 조합합니다.
- UI가 상현님의 시나리오 결과를 소비하도록 입출력을 맞추고, 화면·알고리즘·데이터 접근·설정의 책임을 구별합니다.
- 운영 상세에서 입력 사건, 바뀐 상태·ETA, 고객에게 제공할 정보를 따라갈 수 있게 합니다. 외부 시스템 연결은 필수 시연 전제로 삼지 않습니다.
- 성공 기준: 같은 합성 배송 건의 상태·ETA·갱신 시각이 운영 화면과 고객 미리보기에서 일치하고, 미확정 정보가 정상 값처럼 보이지 않습니다.
- 지인님 작업에서 제외: 시나리오 기능·알고리즘 구현은 박상현님 담당입니다. 실제 TMS 구축, 권역·배차 최적화, AI 학습·실제 ETA 모델, 실시간 데이터 수집, 지도 일체, 실제 알림 발송, 결제·주문 처리, 운영 배포는 이번 준비 범위 밖입니다.

## Information architecture

### 2026-09-14 사용자 지정 배포 기준

**상단은 뷰어 선택, 좌측은 운영 업무 메뉴**입니다. 이전 `배송 현황 / 단말 관제 / 고객 보기`를 같은 좌측 축에 두던 구성은 이 결정으로 대체합니다. 이는 사용자가 지정한 배포 기준을 로컬 레퍼런스에 일치시킨 것이며, 실제 배포 변경이나 운영 기능 완료를 주장하지 않습니다.

| 위치 | 항목 | 로컬 경로 | 역할 |
|---|---|---|---|
| 상단 | 운영 뷰어 | 마지막 운영 업무 경로 | 주문·배송 업무 확인 |
| 상단 | 고객 뷰어 | `#/customer` | 선택 배송의 고객 안내 |
| 상단 | 배송원 뷰어 | `#/driver` | 선택 차량·배송의 작업 정보 표본 |
| 좌측 | 주문 관리 | `#/orders` | 주문 목록·배송 연결의 화면 자리. 주문 데이터 미연결 상태 표시 |
| 좌측 | 배송 목록 | `#/deliveries` | 배송 검색·필터·목록·선택 |
| 좌측 | 배송 관제 | `#/control` | 배송 진행·ETA·사건 이력·알림과 우측 관리 영역 |
| 관제 우측 탭 | 배송 관리 | `#/control` 내부 탭 | 선택 배송 정보·차량·단말·완료·수신 상태 확인 |
| 관제 우측 탭 | 장치 표시 | `#/control` 내부 탭 | 차량 장착형 TMS 표시 예시 |
| 좌측 하단·검토용 | 디자인 가이드 | `#/design` | 화면 구성 계약과 공식 자산·공통 요소 검토 |

배송 관제 우측에 배송 관리를 흡수합니다. 독립된 네 번째 업무 메뉴나 좌측 고객 메뉴를 추가하지 않습니다. 가운데 상세는 사건 이력·알림 미리보기입니다. 주문 관리와 배송원 뷰어는 이번 범위에서 화면 구성 표본이며 주문 CRUD·배차·배송 완료 처리 동작을 새로 만들지 않습니다.

좌측 업무 메뉴를 누르면 해당 운영 뷰어로 이동합니다. 고객·배송원 뷰어에서는 좌측 업무 메뉴가 선택되지 않으며, 운영 뷰어로 돌아가면 마지막 운영 업무 페이지를 복원합니다. 가이드는 검토용 별도 경로이며 공통 상단·좌측 구성과 같은 이름을 사용합니다.

선택 배송·시나리오·필터는 뷰어와 업무 메뉴 사이에서 유지합니다. 뒤로/앞으로 이동 시 상단 뷰어·좌측 선택·제목·본문이 현재 경로와 일치해야 합니다. 새 뷰어에서도 기존 `viewModel`, `etaCard`, `customerCard`의 ETA 미확정·갱신 지연·완료 의미를 유지합니다.

좌측 메뉴는 같은 높이의 직사각형 영역에 글자를 중앙 정렬하고, 선택 시 공식 미트박스 레드 `#E60028` 글자와 **오른쪽 3px 직선**으로 강조합니다. 둥근 선택 배경과 그림자는 사용하지 않습니다. 상단 뷰어는 **하단 3px 직선**을 사용하며 강조선은 레이아웃 높이를 늘리지 않는 절대 배치로 표시합니다. 왼쪽 inset 그림자·세로 강조선은 메뉴뿐 아니라 모든 요소에서 사용하지 않습니다. 배송 행·차량 행의 선택, 안내·경고·장치 알림·고객 메시지도 같은 규칙을 따릅니다. 선택은 배경과 글자, 상태는 문구·배지·표면색으로 구분합니다.

헤더는 데스크톱 56px, 좁은 화면은 브랜드 44px·뷰어 44px의 두 행과 경계선으로 구성합니다. 제목 영역은 헤더 아래 20~24px 여백으로 시작합니다. 운영 업무 페이지에서는 상단 탭과 중복되는 운영 뷰어 보조 제목을 숨기고 페이지 제목부터 표시합니다. 배송 목록의 선택 카드에서 차량·변경 사유는 세로로 쌓고 각 행의 라벨 64px·간격 12px와 값 영역을 맞춥니다.

B안의 좌측 메뉴와 우측 본문 배치는 유지하며 좁은 화면에서는 상단 뷰어를 헤더의 둘째 줄로 배치합니다. 공통 시나리오 팝업은 배송·관제·고객·배송원 표본에 사용하며, 주문 미연결 페이지와 디자인 가이드에서는 숨깁니다. 디자인 가이드의 컴포넌트 절은 별도 상태 선택기로 비교합니다.

주문 입력 계약·실제 배송원 작업 API와 기기 UI 규격은 이번 요청에서 확정하지 않았습니다. 관제 지도 펼치기는 기존 빈 미리보기 안내를 유지합니다. 자세한 현행 메뉴 계약은 [메뉴 구성](docs/menu-plan.md)을 따릅니다.

## Design principles

1. 시간 범위와 변경 이유를 먼저 읽게 합니다. 도착 시각 한 점으로 정확도를 과장하지 않습니다.
2. 배송 단계, 진행 순서, ETA 상태를 별도로 표현합니다. 각 의미는 [도메인 문서](docs/domain-and-scenarios.md)를 따릅니다.
3. 원문 목표와 데모 수치를 구분합니다. 80% 목표를 달성률 카드나 실제 성능 그래프로 표현하지 않습니다.
4. 한 요소의 변형을 Asset Page에 모읍니다. 화면마다 다른 배지·시간 카드·용어를 만들지 않습니다.
5. 운영 정보의 밀도와 고객 화면의 단순함을 각각 조절하되 같은 배송 데이터를 표현합니다.
6. 화면의 색·배치·필터가 상태 전이와 ETA 계산을 소유하지 않게 합니다. 필요한 데이터는 합의한 조회 결과에서 받습니다.

## Visual language

### Color

아래는 승인된 B안의 기준이며 현재 `styles.css`의 CSS 토큰에 반영했습니다. B안 시안값과 공개 화면 관측값을 구별합니다. 실제 화면에서 관측한 값도 공식 CI 지정색이라는 뜻은 아닙니다.

| 역할 | 기준 값 | 근거와 사용 |
|---|---|---|
| 주 액션 | `#263345` | 승인 B안의 절제된 짙은 액션색. 공개 홈페이지 관측색이 아닌 디자인 제안 |
| 브랜드 이름 강조 | `#DB0E64` | 공개 홈페이지 검색 버튼 배경 관측값을 B안의 텍스트 이름에 제한적으로 사용. 공식 CI·로고 색 측정값은 아님 |
| 주요 글자 | `#232221` | 공개 홈페이지 섹션 제목 관측 |
| 보조 글자 | `#61656E` | B안 시안값. 공개 홈페이지 관측값 `#413F3D`와 구별 |
| 기본 표면 | `#FFFFFF` | 공개 화면 및 버튼 배경 관측 |
| 작업 영역 표면 | `#F3F4F6` | B안 시안값. 공개 보조 표면 관측값 `#F2F4F7`을 참고 |
| 선택 행 | `#F0F3F7` | B안 시안값. 짙은 왼쪽 표시와 함께 선택을 전달 |
| 구분선 | `#DCE0E6` | B안 시안값. 공개 테두리 관측값 `#E4E7EC`과 구별. 포커스 표시에 단독 사용하지 않음 |

| 완료 | `#15803D` | 데모 의미색 제안 |
| 오류 | `#B42318` | 데모 의미색 제안. 브랜드 액션색과 아이콘·문구로 구별 |

이전 조사에서 계산한 흰 배경 대비는 `#DB0E64` 4.93:1, `#232221` 15.88:1, `#413F3D` 10.48:1입니다. 이는 해당 단색 조합의 계산 결과이며 변경된 B안 전체의 접근성 검증 결과가 아닙니다. B안의 실제 요소 대비는 개별 표본 단계에서 확인합니다. 미확정 정보도 충분한 대비의 텍스트로 표시합니다.

### Typography and layout

- 공개 홈페이지 computed font stack은 Pretendard를 우선 지정합니다. 실제 사용 폰트 파일·버전·라이선스 자산은 아직 확보하지 않았습니다.
- 데모 제안: Pretendard 우선, 한국어 시스템 글꼴 fallback. 본문 14~16px, 보조 정보 12~13px, 섹션 18~20px, 화면 제목 24px, 고객 ETA 28~32px.
- 숫자와 시간은 자리 폭이 일정한 숫자 표현을 검토합니다. 시간의 날짜·시간대는 상세 또는 화면 기준 정보에 둡니다.
- 간격 기준: 4/8/12/16/20/24/32px. B안 작업 영역 여백 20px, 목록 셀 세로 여백 10px의 조밀한 구성을 참고합니다. 입력 높이 40px, 행 높이와 여러 줄 정보의 여백은 Asset Page에서 검토하며 작은 글씨로 밀도를 높이지 않습니다.
- 모서리 기준: B안의 기본 버튼·패널 3px, 고객 미리보기 외곽 6px. 기존 A안의 6/8/12px 제안 대신 B안의 절제된 형태를 따릅니다. 공개 사이트 공통 토큰으로 주장하지 않습니다.
- 흰 표면과 얇은 경계로 구분하고 그림자는 상세 패널에만 제한합니다.
- 모션은 선택·펼침·값 변경에만 짧게 사용합니다. 반짝임, 자동 재생, 위치 이동 연출은 제외합니다.
- 아이콘은 선형 16/20px 체계 후보입니다. 한 아이콘 세트로 통일하며 패키지는 아직 선택하지 않습니다.

## Components

공통 목록과 상태는 [Asset Page 명세](docs/asset-page-spec.md)를 따릅니다. 기본 UI → 배송 상태 → ETA와 변경 이력 → 화면 조합 순으로 검토합니다.

핵심 요소는 배송 단계 배지, ETA 범위, 순서 표시, 이벤트 타임라인, ETA 변경 비교, 갱신 시각, 알림 미리보기입니다. 운영·TMS 표시 예시·고객 안내가 같은 배송 결과를 사용합니다. `view-components.mjs`에서 공통 표현을 제공하고 디자인 가이드에도 같은 렌더러를 사용합니다. 가이드는 현재 사용 요소를 모은 첫 버전이며 모든 정책·상태 조합을 승인한 것은 아닙니다.

## Accessibility

- 디자인 목표는 WCAG 2.2 AA를 참고한 읽기·조작 경험입니다. 인증이나 준수 완료를 주장하지 않습니다.
- 배지에는 색과 함께 한국어 이름, 필요하면 아이콘을 표시합니다. [Carbon Status indicators](https://carbondesignsystem.com/patterns/status-indicator-pattern/)
- 키보드로 검색, 필터, 배송 상세, 미리보기 전환이 가능하게 설계합니다. 상세 패널 닫기 후 원래 트리거로 포커스를 돌립니다.
- ETA 갱신은 사용자의 포커스를 강제로 이동시키지 않고, 선택 배송의 변경 내용을 문맥과 함께 알립니다. [W3C Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)
- 시간 범위, 변경 사유, 마지막 갱신은 색·hover·아이콘만으로 숨기지 않습니다. 타임라인은 순서가 있는 목록으로 읽힐 수 있어야 합니다.
- 모션 감소 설정에서는 이동·강조 애니메이션을 생략합니다.

## Responsive behavior

- 우선 검토 크기 제안: 운영 화면 1440px와 1280px, 고객 미리보기 390px와 360px 폭.
- 운영 화면은 데스크톱 중심입니다. 고객 미리보기 때문에 목록 열을 과도하게 압축하지 않습니다.
- 공간이 부족하면 고객 미리보기를 별도 화면으로 옮기고, 운영 목록의 부가 열은 상세에 둡니다.
- 고객 화면에서는 긴 상태·사유를 줄바꿈합니다. hover에 의존하지 않습니다.

## Interaction states

| 상태 | 표현 계약 |
|---|---|
| 로딩 | 고정된 시나리오의 로딩 표본. 실제 서버와 연결되었다는 표현 금지 |
| 비어 있음 | 조회 결과 없음과 원본 데이터 없음의 사유를 구분 |
| 오류 | 해당 요소에서 설명. 배송 자체가 실패한 것으로 바꾸지 않음 |
| 변경 | 이전·현재 ETA, 변경 사유, 갱신 시각. 실제 재계산 완료 주장 금지 |
| 완료 | 완료 상태와 완료 시각. 앞으로 도착할 ETA와 구별 |
| 비활성 | 사용할 수 없는 이유를 인접 텍스트로 설명 |
| 미확정·오래된 정보 | “도착 예정 시간 확인 중”, “마지막 확인 …”. 정상·0분·정시로 대체 금지 |

## Content voice

### 2026-09-13 디자인 가이드 세부 검토

- 이번 수정·검토 범위는 디자인 가이드 한 페이지와 지적된 하단 메뉴 이름입니다. 다른 업무 페이지의 전체 디자인 검토로 확장하지 않습니다.
- 제목과 짧은 메타 정보는 구분점 대신 자연스러운 제목, 간격, 줄바꿈으로 구별합니다. 설명 문장의 `발송·전달·수신` 같은 병렬 표기는 유지합니다.
- 사용자가 좋다고 한 사건 이력의 시각·세로선·내용 배치를 유지합니다.
- ETA의 1열 보조 정보에는 2열 표의 교차 테두리를 적용하지 않습니다. 항목 사이의 수평선만 사용합니다.
- 좁은 하단 메뉴는 보조 문구와 두 줄 이름의 위계를 나누고 중앙 정렬합니다.
- 넘침 여부만으로 레이아웃 검증을 완료하지 않습니다. 내부 선, 여백, 제목, 메타 정보와 줄바꿈을 실제 화면에서 확인합니다.
- ETA 비교 카드는 머리·유연한 본문·하단의 세 영역으로 구성합니다. 같은 행의 높이 차이는 본문이 흡수하고, 하단은 내용 길이와 알림 유무에 관계없이 세로 padding 12px, 가로 padding 14px, 요소 간 gap 12px를 유지합니다. 자식 요소의 바깥 margin으로 이 간격을 만들지 않습니다.
- 상태 이름과 카드 사이 간격은 부모의 gap 5px로 정합니다. 상태 이름의 높이를 숫자로 빼서 카드 높이를 맞추지 않습니다.

짧고 정중한 한국어를 사용합니다. 고객 화면에서는 “예정”, “확인 중”, “변경”을 정확히 구별합니다. “AI 정확도 80%”, “실시간 연결됨”, “알림 발송 완료”처럼 증거 없는 문구는 사용하지 않습니다.

미리보기 상단에는 “시연용 · 가상 배송 데이터”를 표시합니다. 개발 도구명이나 데이터 필드명을 고객 메시지에 노출하지 않습니다.

## Implementation constraints

- 현재 단계: 세 업무 메뉴와 디자인 가이드를 로컬에서 연결했습니다. [검증 기록](docs/ui-verification.md)과 [UI 연결 명세](docs/ui-data-contract.md)를 함께 확인합니다.
- 정적 HTML/CSS/JavaScript와 합성 조회 결과를 사용합니다. 프레임워크·패키지 설치·실제 장치·API·상태 전이·ETA 알고리즘·서비스 서버·배포는 미착수입니다.
- 원문 요구의 스캔·기사 앱·교통정보는 후속 데모에서 합성 이벤트로만 설명할 후보입니다.
- 프레임워크 선정은 다음 단계의 결정 사항입니다. 이미 있는 CLEVER 서비스를 재사용한다는 전제를 두지 않습니다.
- 현재 UI 검증은 가이드 상태 표본, 운영·TMS·고객 ETA 일치, 메뉴·조회·초기화, 좁은 폭, 키보드, 지도 없는 구성을 대상으로 합니다. 실제 공급자 연결 뒤에는 같은 기준을 다시 확인합니다.
- API·데이터 접근은 시나리오 공급자와 UI 사이의 경계로 준비합니다. 외부 API·실제 서버 구현은 시작하지 않으며, Config에는 표기·선택 값만 두고 조회 필터는 결과를 바꾸지 않습니다.
