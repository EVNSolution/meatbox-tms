# 미트박스 TMS 데모 준비

문서 2번 고객 배송 트래킹과 3번 다이나믹 ETA를 대상으로, 임지인님의 UI/UX 디자인 레퍼런스와 아키텍처 작업을 진행하는 디렉토리입니다. 사용자 지정 배포 기준에 따라 **상단 운영·고객·배송원 뷰어 / 좌측 주문 관리·배송 목록·배송 관제 / 하단 디자인 가이드**를 로컬 레퍼런스에 반영했습니다. 이 원본 레퍼런스는 합성 표본을 사용하며 배포 서비스의 구현 상태를 나타내지 않습니다.

- 기준일: 2026-09-14
- 시연 목표일: 2026-09-16 수요일. 사용자의 “3일 뒤 수요일” 기준입니다.
- 확정 방향: **운영 화면 중심 + 고객 배송조회 미리보기**
- 현재 화면: **주문 관리 `#/orders` / 배송 목록 `#/deliveries` / 배송 관제 `#/control` / 고객 뷰어 `#/customer` / 배송원 뷰어 `#/driver` / 디자인 가이드 `#/design`**. [페이지 구성과 실행 방법](docs/terminal-view.md)
- 공통 구조: **상단 뷰어 선택 + 좌측 운영 업무 메뉴 + 우측 본문**. 배송 관제 우측 탭에 배송 관리를 흡수했습니다. 메뉴 이동에도 같은 선택 배송과 합성 시나리오 결과를 유지합니다.
- 결과물 성격: 합성 시나리오로 설명하는 데모. 실제 서비스·실제 운영 성능의 증명이 아닙니다.
- 지도: 관제의 **지도 펼치기** 버튼으로 빈 미리보기와 안내 문구만 표시합니다. 실제 지도 이미지, SDK, 경로선, 위치 추적, 지오코딩은 제외합니다.
- 시나리오: 페이지 본문 밖의 공통 플로팅 패널입니다. 왼쪽 핸들로 이동하고 접거나 펼칠 수 있습니다.
- 디자인 가이드: 화면 구성 계약과 공식 로고·앱 아이콘·기능 아이콘·색·굵기·Radius 및 배송 상태를 비교합니다. [전체 검토 항목](docs/asset-page-spec.md)의 모든 상태가 완성되었다는 뜻은 아닙니다.

## 역할과 전제

- **박상현:** 시나리오 기반의 B&W 기능·알고리즘 구현.
- **임지인:** UI/UX Design Reference With Architecture. 디자인 요소, 도메인 표현, 화면·데이터·설정의 경계를 준비합니다.
- 두 작업은 시나리오 입력과 배송 결과의 정의를 맞춰 조합합니다. 역할은 사용자의 최신 설명을 기준으로 합니다.
- 미트박스의 기존 배송 시스템·API 보유 여부는 **미확인 가정**입니다. 공개 커머스 사이트를 확인한 것만으로 내부 시스템이나 연동 지원을 단정하지 않습니다.
- 외부 API 연결은 향후 선택지입니다. 이번 설계는 UI와 시나리오 로직을 나누고, 필요할 때 데이터 공급 방식을 바꿀 수 있는 정도로 잡습니다.

## 작업 경계

좌측 세 업무 메뉴, 상단 세 뷰어, 공식 자산 기반 디자인 가이드, 공통 `view-model.mjs`·`view-components.mjs`, [UI 데이터 연결 명세](docs/ui-data-contract.md)를 합성 표본으로 준비했습니다. 다음 단계는 이 경계를 상현님 구현의 합의된 결과에 연결하고 실제 통합 동작을 검증하는 일입니다. 최종 API·주문과 배송의 실제 관계·장치 수신 정책은 아직 확정하지 않았습니다.

첨부 DOCX는 원래 위치에서 읽었습니다. 기밀 주문 RAW 및 메일의 Drive 링크는 열거나 복사하지 않았습니다. 이 폴더의 요구사항 정리 역시 내부 검토용이며, 외부 배포 대상에 자동 포함하지 않습니다.
