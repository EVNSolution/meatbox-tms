# 미트박스 TMS

날짜별 주문을 배차안으로 계산하고, 확정한 배차의 배송 진행을 운영·배송원·고객 화면에서 조회하는 시스템입니다. 자원 관리에서는 별도 등록부의 차량과 지역 코드를 관리합니다.

**처음 오셨다면 [문서 안내](docs/README.md)에서 역할에 맞는 경로를 선택하세요.** 운영 중 문제가 있다면 [운영 절차](docs/operations.md)를, 실제 고객·배송원에게 서비스를 확대하려면 [운영 전환 기준](docs/production-readiness.md)을 먼저 확인하세요.

> 문서 기준: 2026-09-28, 구현 커밋 `40387756a5c02d02af6ac134d4a2d5bfa1146bef`. 이 문서는 해당 코드의 동작을 설명합니다. 현재 서버의 배포 버전·저장 설정·데이터·기기 수신 여부는 별도 확인 대상입니다. [이번 정비의 근거와 검증 범위](docs/evidence/documentation-audit-2026-09-28.md)

## 주요 업무

| 업무 | 현재 제공하는 흐름 | 반드시 구분할 점 |
|---|---|---|
| 배차 관리 | 날짜 선택 → 후보 선택 → 계산안 검토·핀배차 → 전체 배차 전송 | 계산안은 초안입니다. 전송은 서버의 배차 확정이며 외부 앱 수신 증거가 아닙니다. |
| 배송 관제 | 선택 날짜의 확정 차량·배송·완료 조회, 순서와 배송 기록 관리 | 과거 날짜는 읽기 전용입니다. 위치·ETA에는 원본·계획·시연 값이 섞일 수 있습니다. |
| 자원 관리 | 차량 표, 등록된 지역 코드 선택, 코드 추가·이름 변경, 일괄 저장 | 일별 배차와 분리된 SQLite 등록부입니다. 코드 한 개에 여러 차량을 연결할 수 있습니다. |
| 배송원 화면 | 확정 배차 조회, 출발·도착·완료, 요청 확인, 날짜별 원본 이력 | 사진은 브라우저 임시 미리보기입니다. 실제 증빙 저장·기사 신원 검증은 별도 과제입니다. |
| 고객 화면 | 주문 상태·예상 시간·알림 조회, 페이지 내 시연 | 고객별 서버 권한이 구현되었다는 의미는 아닙니다. 시연 차량 위치는 실제 GPS가 아닙니다. |

## 먼저 지킬 계약

- **초안과 확정 배차를 구분합니다.** 확정 후 수정안을 편집하는 동안에도 기존 확정 배차는 유지됩니다.
- **오늘은 서울의 실제 날짜입니다.** 원본 자료의 기준일·발표일로 오늘을 대체하지 않습니다. 오늘 자료가 없으면 빈 상태로 표시합니다.
- **상태 보존은 설정과 저장 성공에 달려 있습니다.** `DISPATCH_STATE_DIR`을 설정한 날짜별 체크포인트와 메모리 시나리오는 지속성이 다릅니다.
- **자원 등록부와 일별 배차는 다른 자료입니다.** 자원 코드 저장만으로 주문 재배정이나 SHP 경계 편집이 되지 않습니다.
- **확인되지 않은 데이터는 만들지 않습니다.** 후보 그룹·표시 차량번호·계획 ETA를 실제 인력·차량 신원·운행 이력으로 해석하지 않습니다.

자세한 상태 전이는 [도메인과 상태](docs/domain-and-state.md), 저장 위치와 복구 경계는 [운영 절차](docs/operations.md)에 있습니다.

## 실행과 개발

Node.js **22.13 이상**이 필요합니다. Express·WebSocket 기반의 Node 서버와 브라우저 ES 모듈을 사용하며, 자원 등록부는 Node 내장 SQLite를 사용합니다. 설치와 검증의 기본 명령은 다음과 같습니다.

```sh
npm ci
npm test -- --test-concurrency=1
```

서버 실행에는 `PUBLIC_ORIGIN`과 계정 파일 설정이 필요합니다. 운영 계정을 복사하지 않고 시작하는 전체 절차는 [개발 환경](docs/development.md)에 있습니다. 원본 주문은 저장소에 포함되지 않습니다. 원본이 없는 로컬 시나리오 실행과 날짜별 실제 자료 검증을 구분하세요.

## 운영 전환 상태

이 코드에는 역할·고객·차량별 서버 접근 제어, 사진 영구 저장, 실제 GPS 수신, 실제 미트박스 API 수신 계약, 외부 기사 앱 수신 확인까지 완료된 통합 경로가 없습니다. 로그인과 화면 선택은 그 기능을 대신하지 않습니다. [보안·접근 경계](docs/security-and-access.md)와 [운영 전환 기준](docs/production-readiness.md)에 부족한 항목과 완료 조건을 정리했습니다.

별도 B_AREA DB 작업과 Web Push 파일럿은 이 문서 기준 커밋의 구현에 포함되지 않습니다. 오래된 문서의 테스트 수·차량 수·배포 성공 기록은 해당 시점의 증거입니다. 현재 완료 여부를 판단하는 방법은 [검증 가이드](docs/verification.md)를 따릅니다.
