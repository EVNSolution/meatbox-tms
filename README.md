# 미트박스 TMS 검토 작업 공간

로그인 후 시연 안내에서 시작하고, 운영 뷰어와 고객 뷰어를 같은 탭 안에서 전환하는 데모입니다. 첫 화면에는 팀 회의용 원본 검토 링크도 남겨 둡니다. 기존 배송 현황 시스템과 연결할 화면을 검토하며, 실제 차량 TMS 연결이나 고객 알림 발송을 수행하지 않습니다.

## URL과 소유 범위

운영 주소: **https://3.36.96.156/**

| 경로 | 용도 | 코드 |

`workspaces/`의 두 원본은 보존용입니다. 박상현 원본 기준 커밋은 `f41af790be7529d4d2da9e8ac44826acdd120a50`이며, 원본 파일별 SHA-256은 `docs/source-snapshots.json`에 있습니다. 원본 코드 수정은 별도 작업으로 검토하고, 통합 변경은 `apps/combined/`와 루트 게이트웨이에 적용합니다. `/scenario/` 경로와 WebSocket 주소만 HTTP 응답 시 치환하여 원본 바이트를 유지합니다.

시나리오와 합본은 **하나의 메모리 시뮬레이션**을 공유합니다. 어느 화면에서든 단계 변경/리셋하면 접속한 모든 검토자에게 반영됩니다. 서비스 재시작 시 시뮬레이션과 로그인 세션은 초기화되고 계정은 유지됩니다. UI/레이아웃은 독립 표본입니다.

합본은 차량 V1 한 대와 배송 8곳을 표현합니다. 고객 공식 ETA와 계속 계산되는 ETA를 분리하며, 원본의 단일 시각을 시간 범위로 바꾸지 않습니다. 실제 도착, 배송 완료, 단말 수신 여부도 각각 구분합니다. `customer?id=S5`는 시연 배송 선택이며 로그인 권한을 대신하지 않습니다.

두 뷰어 상단의 공통 **시연 가이드**에서 현재 단계, 시연 시각, 다음 단계의 시각과 바뀔 내용을 확인할 수 있습니다. 주문 접수 → 피킹 → 라벨 부착 → 상차 대기 → 배송 출발을 진행한 뒤, **도착까지 시간 진행 → 배송 완료 처리**로 첫 배송지부터 마지막 배송지까지 시연합니다. 도착은 기존 이동·교통 계산을 거치며, 완료 처리는 도착 후 현재 시각으로 하차 완료 스캔을 기록합니다. 자동 주행·자동 하차 완료와 배속도 계속 사용할 수 있습니다. 단계별 전체 설명과 최근 변동 시각은 가이드 안에서 펼쳐 봅니다.

단말 관제의 지도 미리보기는 보편적인 1080px 높이 화면의 2/3인 **720px 높이**로 펼칩니다. 현재 브라우저 창의 높이에 따라 줄어들지 않고, 페이지와 함께 스크롤됩니다. 합본과 `/ui-layout/`에 같은 `map-preview.css`를 적용하며 UI 원본 파일은 보존합니다. 기존처럼 빈 지도 영역이며 실제 지도 연결은 포함하지 않습니다.

시연의 **고객 뷰어**는 상현님 고객 시나리오의 주문·ETA·지도·배송 타임라인·알림을 사용하는 별도 페이지입니다. `mobile-customer.html`과 `mobile-customer.css`가 화면을 구성하고, 인증된 `/scenario/common.js`와 `/scenario/customer.js`가 같은 시뮬레이션에 연결합니다. 768px 미만에서는 프레임 없이 화면 너비에 맞춘 한 열을 사용합니다. 큰 화면에서는 왼쪽 390px 모바일 뷰어 안에서 고객의 주문·지도·알림을 스크롤하고, 오른쪽 배송 타임라인을 함께 확인합니다. `?id=S5`로 특정 매장을 바로 열 수 있으며 실제 결제나 알림 발송은 하지 않습니다. 디자인 가이드는 합본 메뉴에서 제외하고 원본 경로로 유지합니다.

합본 상단에는 **차량 진행**과 **보고 있는 고객 배송**을 따로 표시합니다. 시연 주문 고객 S5와 현재 목적지의 관계, 앞선 미완료 배송 수를 실제 순서로 안내합니다. **최근 변동**은 이 페이지를 연 뒤 수신한 단계·고객 상태·공식 ETA·도착/완료 시각·알림의 전후 값이며, 단순 시계 진행과 계속 계산되는 ETA는 제외합니다. 초기화하면 비교 기록도 비웁니다. 뷰어는 같은 브라우저 탭에서 전환되며 같은 `id`로 선택 배송을 유지합니다. 고객 뷰어에서 매장을 바꾸고 운영 뷰어로 돌아와도 그 배송을 유지합니다. 고객 렌더러와 시연 가이드는 페이지당 하나의 인증된 상태 연결을 공유합니다. 원본 시뮬레이션과 주문·ETA·지도 동작은 그대로 재사용합니다.

## 로컬 실행

Node.js 22 이상을 사용합니다. 별도 번들 빌드 없이 Express와 ws만 설치합니다.

```sh
npm ci
mkdir -p .runtime
node scripts/manage-access.js issue-invite --file .runtime/access.json --output .runtime/invite.txt
PUBLIC_ORIGIN=http://127.0.0.1:3001 ACCESS_FILE=.runtime/access.json PORT=3001 npm start
```

`http://127.0.0.1:3001/dev/register`에서 초대 파일의 코드를 입력하여 가입한 뒤 로그인합니다. 초대 코드는 기본 24시간 내 1회 사용 가능하며 회원가입 링크는 일반 화면에 노출하지 않습니다. 기본 계정/비밀번호는 없습니다.

```sh
npm test
node --check server.js
node --check lib/access.js
node --check apps/combined/app.mjs
git diff --check
```

인증, 익명 HTTP/API/WebSocket 차단, 외부 Origin 거부, 세션 종료, 초대 1회 사용, 원본 보존, ETA 의미와 UI 팝업 범위를 검증합니다. CSS는 실제 브라우저에서 넓은 화면과 좁은 화면을 함께 점검합니다.

## 배포와 계정 관리

`deploy/meatbox-gateway.service`와 `deploy/Caddyfile`을 사용합니다. 자세한 배포/롤백/초대 발급 절차는 [운영 문서](docs/operations.md)를 참고하세요. 계정 파일, 초대 코드, SSH 키는 Git에 넣지 않습니다.
