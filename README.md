시나리오와 합본은 **하나의 메모리 시뮬레이션**을 공유합니다. 실시간 V1 배송지에서 수동 시나리오를 선택하면 접속한 모든 검토자에게 반영됩니다. 자동으로 시간이 흐르거나 다음 단계로 넘어가지 않습니다. 서비스 재시작 시 시뮬레이션과 로그인 세션은 초기화되고 계정은 유지됩니다. UI/레이아웃은 독립 표본입니다.

현재 포함된 차량 130대, 배송지 4,523곳, 9,090박스는 화면 구조와 밀도를 검토하기 위한 임시 표본이며 제품의 확정 수량이 아닙니다. 이 가운데 차량 V1의 배송지 8곳과 60박스만 기존 원본 시뮬레이션과 직접 상호작용합니다. V2부터 V130까지는 차량마다 배송지 35곳과 배송지당 2박스를 가진 화면 검토용 합성 표본입니다. 합성 차량의 `capacityBoxes`는 `null`이며 70박스를 적재 상한으로 해석하지 않습니다. 확인되지 않은 주소, 좌표와 ETA도 만들어 내지 않습니다. 이후에는 정제한 실제 데이터가 차량, 배송지와 박스 수의 기준이 됩니다. `customer?id=S5`는 시연 배송 선택이며 로그인 권한을 대신하지 않습니다.

**배차 관리**는 좌측 차량 목록과 전체 주문 지도를 함께 사용합니다. 날짜별 지도는 낮은 배율에서 표시할 마커를 고정해 이동 중 깜빡임을 줄이고, 확대 시 추가 마커를 모두 선명하게 표시합니다. 줌 14 이상에서는 모든 개별 마커를 표시합니다. 숫자 묶음은 표시하지 않습니다. 차량을 바꿔도 전체 주문 데이터는 유지하고 선택 차량의 주문을 앞쪽에 강조하며 차량 마커는 표시하지 않습니다. `/scenario/api/route-data`에 등록된 실제 좌표만 DSV 목적지 마커로 표시하고 좌표 없는 주문은 위치 미등록 건수로 알립니다. 확인되지 않은 좌표를 만들거나 배송지를 직선으로 잇지 않습니다. 차량의 고정 출발 기준과 전체 배정 배송의 완료 예상은 서로 다른 항목이며 제공되지 않은 값은 `미등록`으로 둡니다. 배차·관제 지도는 Ctrl 또는 Cmd를 누른 스크롤로 확대·축소하며 일반 스크롤에서는 페이지를 이동하고 DSV MapLibre 스타일의 안내 가리개를 표시합니다. 고객·배송원 폰 지도는 보조 키와 안내 가리개 없이 일반 스크롤로 확대·축소합니다. 배송원 순서 편집 중 지도 확대 잠금은 유지합니다. **주문 시나리오** 팝업은 수신한 전체 배송의 박스 합계를 기준 물량 100%로 잡고 목표 물량을 80%부터 120%까지 미리 봅니다. 기본값과 초기화 값은 100%입니다. 이 미리보기는 원본 주문 마커와 개별 박스 수, 차량·배송지 수, 배송 상태, ETA, 알림과 배차 순서를 변경하지 않습니다. 기준값이 누락되면 `미확인`으로 표시하고 명시적인 빈 배열이나 합계 0은 0으로 유지합니다. 실제 물량 증감 방식, 배차 알고리즘과 성능 평가 지표는 정제된 데이터와 알고리즘 계약이 들어온 뒤 결정합니다.

세 뷰어의 공통 **플로팅 시연 가이드**는 **주문 관련**의 `접수 완료 · 피킹 중 · 출고 준비`, **배송 관련**의 `배송 중 · 배송지 도착 · 배송 완료` 버튼을 제공합니다. 실시간 V1의 선택 배송지에서 여섯 장면을 임의 순서로 즉시 전환합니다. 다른 장면을 한 번 누르면 한 번만 계산하고, 이미 활성인 장면을 다시 누르면 상태를 반복 전파하지 않습니다. 합성 배송지는 시나리오 변경을 막고 화면 검토용 데이터임을 표시합니다. 자동 주행, 자동 하차 완료, 배속, 사고와 정차 지연 버튼은 없습니다. 펼친 패널은 이동할 수 있고 접으면 작은 시연 가이드 버튼만 남습니다. 시나리오 선택은 기존 배송팁, 운영자 수동 안내와 고객 약속 시간대를 지우지 않습니다. 선택 배송의 도착·완료 장면은 고정 실제 도착 시각을 운영 정확 시각으로 보여 줍니다.

**자원 관리**는 배송원, 차량, 배송지 탭을 제공합니다. 배송원 고유 ID가 없으므로 같은 이름도 차량 ID별 배정 배송원으로 구분하고 당일 배정·완료·잔여·보류 배송지/박스 수를 계산합니다. 보류는 잔여에 포함하고 박스 결측은 `미등록`으로 표시합니다. 성향·평가·메인 권역은 `미등록`이며 [미배정 프로필 후보](docs/driver-profile-candidates.md)만 준비했습니다. 차량의 `region`은 메인 권역이 아니라 **배정 권역**입니다. 배송지 탭은 기존 전체 검색, 차량/상태 필터, 50개 단위 페이지, 선택 카드와 배송팁을 유지합니다. 배송원과 차량 상세의 배정 배송지 이동은 실제 차량/배송지 ID를 사용하며 합성 차량 선택을 V1 운행 명령으로 연결하지 않습니다.

**배송 관제**는 주문 수신 순서로 차량을 나열하고 남은 배송지 수, 박스 수와 제공된 예상 소요 시간을 비교합니다. 차량을 선택하면 지도에 현재 위치와 남은 등록 배송지 마커를 표시하고 우측 차량 카드에서 배송지별 상세를 펼칩니다. 상세를 열어도 현재 차량의 운행 요약은 바뀌지 않습니다. 사건 이력은 실제 발생 기록만 시간순으로 합치고 같은 배송지 ID의 고객 알림을 함께 조회합니다. 지원배차는 진입점과 원자료 미연결 상태를 표시하며 안정 등급, 수락과 재배정 기준을 임의로 만들지 않습니다. 배송 순서 편집은 실시간 V1의 8곳에만 적용합니다.

배송 관제 우측 **배송 관리** 탭에서는 **순서 편집 → 손잡이 또는 위아래 버튼으로 이동 → 변경 저장 / 취소**로 작업합니다. 저장 전에는 다른 화면에 반영되지 않습니다. 배송 중·완료·보류 행은 고정하며, 편집 중 실제 순서나 배송 상태가 달라지면 최신 상태에서 다시 편집하도록 안내합니다. 서버도 기대한 순서·상태와 현재 값을 비교한 후 전체 순서와 ETA를 한 번에 반영합니다. 보류·복원은 편집 모드 밖에서 개별 배송에 적용하며, 시연 주문 고객은 원본 정책대로 보류할 수 없습니다.

시연의 **고객 뷰어**는 상현님 고객 시나리오의 주문·ETA·지도·배송 타임라인·알림을 사용하는 별도 페이지입니다. 운영 뷰어는 계속 계산되는 정확 ETA를 보여 주고, 고객 뷰어는 약속 ETA 앞뒤 30분의 시간대를 보여 줍니다. 정확 ETA가 현재 고객 약속 기준보다 늦게 30분을 초과하면 시간대를 갱신하고 지연 알림을 한 번 추가합니다. 문서의 `실제 도착 대비 ±15분 이내 80% 이상`은 정확도 목표이며 고객 시간대나 알림 임계값이 아닙니다.

`mobile-customer.html`과 `mobile-customer.css`가 고객 화면을 구성하고, 인증된 상태 연결을 재사용합니다. 현재 고객을 대상으로 새 알림 ID가 들어오면 한 번만 팝업으로 보여 주며 최초 이력이나 서버 재시작 뒤 초기 이력을 다시 팝업으로 재생하지 않습니다. 768px 미만에서는 프레임 없이 화면 너비에 맞춘 한 열을 사용합니다. 큰 화면에서는 왼쪽 390px 모바일 뷰어와 오른쪽 배송 타임라인을 함께 확인합니다. `?id=S5`로 특정 매장을 바로 열 수 있으며 실제 결제나 알림 발송은 하지 않습니다.

배송 관제의 고객 알림은 시각, 대상, 제목과 내용을 보여 줍니다. 운영자는 선택 배송에 최대 300자의 안내 문구를 팝업으로 확인한 뒤 시연 기록으로 추가할 수 있습니다. 알림 로그는 정차지별 최근 50건, 전체 최근 1,000건까지만 보존하므로 오래된 항목은 화면 범위를 벗어납니다. **배송원 뷰어**는 선택 배송의 차량 문맥을 따르고 배송지별 최대 500자의 배송팁을 편집합니다. 금일 배차와 날짜별 데모 근무 이력을 분리하며 현재 완료 목록을 과거 이력으로 재사용하지 않습니다. 도착한 현재 배송지는 사진 선택과 고객 요청 필수 확인 뒤 확인 버튼으로 기존 완료 명령을 보냅니다. 사진은 브라우저 임시 미리보기이며 서버 저장이나 외부 전송은 없습니다. 합성 차량에서는 V1 배송 완료 동작을 열지 않습니다.

시연 가이드는 선택 배송과 현재 수동 프리셋을 보여 줍니다. 초기화하면 `접수 완료 · S1`로 돌아가고, 배송 순서나 보류 변경으로 현재 프리셋의 의미가 사라지면 활성 버튼을 임의로 추정하지 않습니다. 헤더로 뷰어를 전환할 때 같은 `id`로 선택 배송과 주문·배송 조회 조건을 유지하고, 운영 뷰어로 돌아오면 마지막 업무 페이지를 복원합니다. 고객 뷰어에서 매장을 바꾸고 운영 뷰어로 돌아와도 그 배송을 유지합니다. 고객 렌더러와 시연 가이드는 페이지당 하나의 인증된 상태 연결을 공유합니다.

공식 미트박스 로고·앱 아이콘과 Pretendard Variable은 `apps/combined/assets/`에 보관합니다. 원본 URL·해시·폰트 라이선스는 `assets/SOURCES.md`와 `assets/OFL-1.1.txt`에서 확인합니다. 좌측 탭은 오른쪽 3px 직선, 상단 탭은 하단 3px 직선으로 강조하며 좌측 그림자나 두꺼운 좌측 강조선은 사용하지 않습니다.

## 실서버 규모 준비

### 날짜별 원본 배차 지도

준비된 `MP_ADM_KMEANS` 주문을 모든 운영·배송원·고객 뷰어에서 사용합니다. 운영 기준일은 **2026-09-16**, 주문 **2,552건 / 4,680박스**이며 335개 날짜를 전환할 수 있습니다. 자료 2025-09-17을 기준일에 대응시켜 요일을 보존합니다. 원본 중복 행도 그대로 합산합니다. 준비 명령, 집계·좌표 기준과 기존 시연 격리는 [날짜별 원본 배차 자료](docs/dated-dispatch-data.md)에 있습니다. 자료는 Git에서 제외하며 이번 자료 연결은 로컬 범위입니다.

차량당 약 70박스와 35개 배송지를 예상 규모로 사용하되 실제 수량 제한으로 고정하지 않습니다. 합본 뷰어는 변경분 전송과 50개 단위 목록을 사용합니다. 수신 계약, 하루 이력 저장의 미구현 범위와 4,550개/9,100개 배송지 검증 결과는 [실서버 데이터 수신 준비](docs/server-data-readiness.md)를 참고하세요. `npm run check:capacity`와 `npm run check:capacity:stream`으로 격리 부하 검증을 재실행할 수 있습니다.

## 로컬 실행

Node.js 22 이상을 사용합니다. 별도 번들 빌드 없이 Express와 ws만 설치합니다.

```sh
npm ci
mkdir -p .runtime
node scripts/manage-access.js issue-invite --file .runtime/access.json --output .runtime/invite.txt
PUBLIC_ORIGIN=http://127.0.0.1:3001 ACCESS_FILE=.runtime/access.json PORT=3001 npm start
```

`http://127.0.0.1:3001/dev/register`에서 초대 파일의 코드를 입력하여 가입한 뒤 로그인합니다. 초대 코드는 기본 24시간 내 1회 사용 가능하며 회원가입 링크는 일반 화면에 노출하지 않습니다. 기본 계정/비밀번호는 없습니다.

```sh
npm test
node --check server.js
node --check lib/access.js
node --check apps/combined/app.mjs
git diff --check
```

인증, 익명 HTTP/API/WebSocket 차단, 외부 Origin 거부, 세션 종료, 초대 1회 사용, 원본 보존, ETA 의미와 UI 팝업 범위를 검증합니다. 다차량 수량, 차량 중심 배차/관제/자원, 30분 초과 경계, 고객 알림과 배송팁의 교차 뷰 동작은 [다차량 테스트 명세](docs/fleet-operations-test-spec.md), 수동 전환과 타이머 제거는 [수동 시나리오 테스트 명세](docs/manual-scenarios-test-spec.md)를 따릅니다. CSS는 실제 브라우저에서 320px, 390px와 1280px를 함께 점검합니다. 배포 여부는 별도 요청과 릴리스 SHA, 인증된 화면 검증으로 따로 확인합니다.

### 시간과 고객 요청 후속 구현 (2026-09-15, 로컬)

기존 이동·하차 시간으로 V1의 마지막 도착과 최종 인도 완료, 잔여 시간을 구분합니다. 주문 시나리오 기간은 시간 입력이 있는 차량의 가장 이른 고정 출발부터 가장 늦은 완료까지이며 집계 차량 수를 표시합니다. 보류가 있는 차량과 시간 입력이 없는 차량은 완료 예측에서 제외합니다. 실제 운행 데이터가 아닌 시뮬레이션 계산값입니다.

S1–S8에 명시적으로 승인된 예시 고객 요청을 제공합니다. 사진 촬영 후 각 필수 요청을 확인해야 완료할 수 있으며 서버도 배송지 ID별 확인 목록을 검사합니다. `/scenario/driver`의 참조 완료 버튼은 현재 배송지의 합본 배송원 화면으로 이동합니다. 원본 파일과 수동 시나리오 선택은 보존합니다. 사진은 저장하지 않으며 지원배차 등급·외부 호출과 실제 근무 이력은 미연결입니다.

시나리오 리모컨의 **다음 배송지** 버튼으로 현재 V1 배차 순서의 다음 대상을 선택할 수 있습니다. 선택 후 기존 여섯 상태 버튼으로 해당 배송지를 시연합니다. 자동 진행은 없고 마지막 배송지에서는 버튼이 비활성화됩니다.

배송원 요청은 현재 배송지의 냉장고·문 앞·실내·직접 전달 아이콘과 상세 요청 문구로 표시합니다. 배송원 화면의 ‘예시 요청’ 배지는 생략하고 시나리오 데이터 출처는 유지합니다. S6는 실내 보관 요청이며 사진 후 해당 필수 체크를 확인해야 완료됩니다.
